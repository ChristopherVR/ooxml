# 支持的功能与保留保证

本页是[稳定性策略](../../../../docs/stability.md)要求产品在被称为稳定版之前提供的书面功能清单与保留保证。它涵盖 Word（`docx-core` 与编辑器）。它说明哪些内容已建模且可编辑，哪些内容在保存时被原样保留却不被理解，以及哪些内容会被拒绝并给出怎样的诊断信息。本页并不声称 Word 与本编辑器的排版结果一致，也不声称保存的文件与 Word 写出的文件相同。

## 保存的工作方式 {#how-a-save-works}

使用 `loadDocx` 加载的文件会保留其原始包。`save` 会重新打开该包，仅修改编辑所涉及的部分：

- `word/document.xml` 被解析为 DOM，并从 DOM 写回。正文按块进行修补：模型未更改的段落、表格或节会保留其源 XML；已更改的块中，模型未包含的标记（未知元素、扩展属性、`mc:` 替代内容、书签、修订标记包装器）则保留在原位置。
- 只有当模型更改了某个部件所包含的内容时，该部件才会被重写：页眉、页脚、脚注或尾注部件，批注及其扩展/标识元数据部件，`word/numbering.xml`，为编辑段落样式格式而需要改动的样式部件，`docProps/core.xml`，编辑器所拥有的 `word/settings.xml` 标志，已编辑的图表和 SmartArt 部件，以及已编辑的数据绑定控件所绑定的 `customXml` 项。
- `[Content_Types].xml` 和关系部件仅在保存过程新增部件或关系时才会更改，以注册这些新增项。
- 其他所有条目均按读取时的原样写回：相同的名称、相同的字节。对未更改的模型进行保存，将返回原始字节。

由编辑器创建（而非加载）的包没有可供保留的源内容，因此会根据模型和内置的默认样式写出。

## 原样保留 {#kept-verbatim}

往返测试 [`preservation.test.ts`](../../../../src/core/docx/preservation.test.ts) 加载一个包含以下内容的包，编辑文本、表格单元格和批注，然后保存，并断言编辑未涉及的每个条目都是字节级一致的（条目列表也保持不变，但新建的批注部件除外）：

| 保留内容                                                                                                                                                                    | 说明                                                                                 |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| `customXml/*` 项、其属性和关系                                                                                                                                              | 仅对用户编辑过的数据绑定控件进行重写。                                               |
| `word/glossary/document.xml` 及其部件（构建基块）                                                                                                                           | 仅读取，用于显示内容控件的占位文字。                                                 |
| `word/vbaProject.bin` 及启用宏的内容类型                                                                                                                                    | 保留，但从不运行。保存文件的扩展名由宿主负责。                                       |
| `word/people.xml`                                                                                                                                                           | 参见下文“批注”。                                                                     |
| `word/fontTable.xml` 及嵌入字体（`word/fonts/*.odttf`）                                                                                                                     | 不用于渲染；与其关系一并保留。                                                       |
| `word/settings.xml`（缩放、`w:extLst`、兼容性和保护元素）                                                                                                                   | 仅修补编辑器所拥有的标志（修订跟踪、奇偶页不同的页眉、断字等）。                     |
| `word/theme/theme1.xml`、`word/webSettings.xml`、`docProps/custom.xml`、缩略图                                                                                              | 主题编辑被拒绝（见下文）。                                                           |
| 未被替换的图片和其他媒体                                                                                                                                                    | 用户替换的图片会获得一个新部件。                                                     |
| 任何类型的未知部件和关系                                                                                                                                                    | 包中编辑器没有读取器的任何内容。                                                     |
| `document.xml` 内部：`mc:AlternateContent`、扩展列表（`w:extLst`）、`w14:`/`w15:` 标记、`w:tblPrChange`、`w:trPrChange`、`w:tcPrChange`、书签、域代码、未知的行内和段落属性 | 位于用户未重组的段落和表格中。已编辑的段落保留其未建模的 `w:pPr` 和 `w:rPr` 子元素。 |

## 批注 {#comments}

批注编辑会在其关系目标处修补原始正文和元数据。未更改的批注会保留其段落、run 格式和未知标记。文本编辑会保留仍然存在的带样式 run。最后一个段落 ID 和持久 ID 使回复、解决状态和 UTC 日期元数据在 `commentsExtended.xml`、`commentsIds.xml` 和 `commentsExtensible.xml` 之间保持一致。被删除的批注会失去其锚点和元数据；新的回复会在其父级范围内获得引用。不透明的编辑器 ID 会与其文档锚点保持一致地映射为十进制的包 ID。people 部件保持原样。本功能不提供富文本批注的编辑控件。

回归测试使用 `comment-preservation.test.ts` 中一个带格式的原生 Word 样例。Word 16 的重新打开/保存检查覆盖了解决、编辑、删除和添加批注（包括回复和非标准部件位置）。六个浏览器绑定检查已保存的回复锚点。

## 已建模且可编辑 {#modeled-and-editable}

文本与字符格式、段落格式和样式（使用以及按样式的格式编辑）、列表和编号定义、节和页面设置、页眉、页脚和脚注、域（可编辑结果，更新域）、批注和修订、内容控件和表单字段、表格（见下文）、超链接和书签、图片、简单形状和文本框、SmartArt、经典图表以及已接受的 ChartEx、文档属性，以及 Word 所读取的编辑限制（表单保护会被强制执行；其他限制会被保留但不强制执行）。

### 表格 {#tables}

行列命令、合并与拆分，以及合并单元格的布局，都通过核心表格结构引擎（`ooxml-core/docx`，`table-structure.ts`）进行编辑，并由能感知合并的写入器（`write-table-structure.ts`）写出。该引擎遵循 Word 的行为：插入行、插入列、删除行、删除列、合并和拆分的结果，均是在小型表格上从 Word 16 中记录下来的（`src/core/docx/__fixtures__/word-table-structure.json`，由 `src/core/scripts/docx/table-structure-word-probe.ps1` 生成），并且有测试逐一检查每一项。

- 编辑后保留下来的行或单元格会保留其 XML 元素，因此模型未包含的 `tblPr`、`trPr` 和 `tcPr` 子元素、扩展属性以及行上的 `w14:paraId` 值都会保留。只有 `tblGrid`、`gridSpan`、`vMerge`、`tcW`、编辑所创建的单元格，以及编辑所添加或删除的行会发生改变。
- 新行会复制其所依据的行（单元格布局、高度、作为标题重复）；新单元格会复制相邻单元格的格式。删除纵向合并的第一行时，合并会移到下一行并清空其文本，这与 Word 的行为一致。
- 嵌套表格会就地编辑：对内层表格的编辑只会改变内层的 `w:tbl`。
- 仅修改文本的编辑永远不会重写任何表格的结构。

以下编辑被拒绝（该命令会被禁用，而写入器无法表达的模型更改会抛出下文的错误）。每一项拒绝都对应 Word 自身会将其转换为普通网格无法容纳的表格：

| 编辑                                                                                                                                                                                                                  | 原因                                                                                                                                                                                                                     |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 在跨多列的合并单元格（横跨若干列的单元格）左侧或穿过它插入列                                                                                                                                                          | Word 会添加 `gridAfter` 行，并插入一个与合并单元格等宽的新单元格。                                                                                                                                                       |
| 删除仅部分覆盖合并单元格的列                                                                                                                                                                                          | Word 会删除整个合并单元格，并使该行变短（`gridAfter`）。                                                                                                                                                                 |
| 将跨多列的单元格拆分为不同的列数，或当它跨越多于一列时拆分为比其跨度更多的列                                                                                                                                          | Word 会重新划分表格网格。拆分为单元格自身的列，以及拆分单列单元格，都可以正常工作。                                                                                                                                      |
| 将纵向合并拆分为行数不等于其高度的形式                                                                                                                                                                                | Word 只接受高度的约数；目前仅实现了完全取消合并。                                                                                                                                                                        |
| 合并一个范围时，其中包含伸出该范围的单元格，或单元格中包含嵌套表格                                                                                                                                                    | 结果会丢失内容或合并的形状。                                                                                                                                                                                             |
| 对具有行偏移（`gridBefore`、`gridAfter`）、修订的行或单元格（`w:ins`、`w:del`、`trPrChange`、`tcPrChange`）、`hMerge`、行或单元格周围的内容控件，或其单元格中含有超链接、域、书签或其他行内标记的表格进行任何结构编辑 | 加载警告“Merged, nested, or complex tables can be read, but their row and column structure cannot be edited safely.”（合并、嵌套或复杂表格可以读取，但其行列结构无法安全编辑。）已说明这一点；其单元格中的文本仍可编辑。 |

对此类表格进行结构性修改时，`saveDocx` 会抛出 `Cannot change the structure of a merged, nested, or complex table. The original DOCX package remains unchanged.`，包不会被修改。

除表格属性对话框所编辑的页边距之外，其他表格级属性（宽度、对齐方式、缩进、边框、样式、外观）会被渲染并保留，但不可编辑：在模型中修改它们会抛出 `Cannot edit table grid widths, width, alignment, indent, borders, or style; ...`。

## 带诊断信息的拒绝 {#refused-with-a-diagnostic}

当模型出现以下情况时，保存会抛出错误，说明原因，并保持源包不变：

- 编辑段落、字符或表格样式目录（`Editing the paragraph style catalog is not supported; source styles.xml is preserved unchanged.`，以及字符和表格的对应变体），编辑器所拥有的按样式格式除外；
- 编辑主题（`Editing the theme catalog is not supported; source theme1.xml/settings.xml are preserved unchanged.`）；
- 重复了块或段落 ID（`Duplicate document block id` / `Duplicate document node id`）；
- 请求的图片、超链接、形状或图表需要一个调用方无法分配的关系；
- 未通过模型验证（`assertValidDocumentModel`：例如文档没有节）。

加载限制为每个包 50 MB、5,000 个条目以及展开后 200 MB（`DOCX_ZIP_LIMITS`）；超出限制的包会在读取任何部件之前被拒绝。

## 加载时报告，保存不做更改 {#reported-at-load-not-changed-by-a-save}

`model.warnings` 列出那些能够加载但其渲染或编辑方式与 Word 不一致的功能，例如嵌入的 OLE 对象（保留，并以占位符绘制）、复杂的 `HYPERLINK` 域（保留为域代码）、表格结构的修订（保留在 XML 中，而不在模型中）、图片项目符号以及部分与样式关联的编号，以及保留但不强制执行的编辑限制。

## 保证的已知限制 {#known-limits-of-the-guarantee}

- **表格单元格中的行内标记**会阻止对该表格进行结构编辑（如上所述），但不会阻止文本编辑。
- **排版不属于保留的信息。** 已编辑段落中的缓存分页提示（`w:lastRenderedPageBreak`）会被丢弃；Word 会重新计算它们。
- 编辑器没有读取器的部件中的内容会被保留，但不会被验证。已损坏的部件仍然保持损坏。
