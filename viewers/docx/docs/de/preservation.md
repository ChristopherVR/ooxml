# Unterstützte Funktionen und die Erhaltungsgarantie

Diese Seite ist die schriftliche Funktionsliste und Erhaltungsgarantie, die die [Stabilitätsrichtlinie](../../../../docs/stability.md) von einem Produkt verlangt, bevor es als stabil gilt. Sie betrifft Word (`docx-core` und den Editor). Sie beschreibt, was modelliert und bearbeitbar ist, was ein Speichern unverstanden übersteht und was abgelehnt wird, mit der jeweiligen Diagnose. Sie behauptet nicht, dass Word und dieser Editor ein Dokument gleich anordnen, und auch nicht, dass eine gespeicherte Datei dieselbe ist, die Word schreiben würde.

## So funktioniert ein Speichervorgang {#how-a-save-works}

Eine mit `loadDocx` geladene Datei behält ihr ursprüngliches Paket. `save` öffnet dieses Paket erneut und ändert nur die Teile, die von den Bearbeitungen betroffen sind:

- `word/document.xml` wird in ein DOM geparst und aus diesem zurückgeschrieben. Der Textkörper wird Block für Block gepatcht: Ein Absatz, eine Tabelle oder ein Abschnitt, den das Modell nicht geändert hat, behält sein Quell-XML. Auszeichnungen, die das Modell in einem geänderten Block nicht führt (unbekannte Elemente, Erweiterungsattribute, `mc:`-Alternativinhalte, Lesezeichen, Umhüllungen von Änderungsverfolgung), bleiben an ihrer Stelle.
- Ein Teil wird nur dann neu geschrieben, wenn das Modell den Inhalt geändert hat: ein Kopf- oder Fußbereich, eine Fußnote oder Endnote, die Kommentare und ihre Metadatenteile für erweiterte und Identitätsdaten, `word/numbering.xml`, die Style-Teile für bearbeitete Absatzformatierungen, `docProps/core.xml`, die Einstellungs-Flags von `word/settings.xml`, die der Editor verwaltet, die bearbeiteten Diagramm- und SmartArt-Teile sowie das gebundene Element `customXml` eines bearbeiteten datengebundenen Steuerelements.
- `[Content_Types].xml` und die Beziehungsteile ändern sich nur, um einen Teil oder eine Beziehung zu registrieren, die der Speichervorgang hinzufügt.
- Jeder andere Eintrag wird so zurückgeschrieben, wie er gelesen wurde: gleicher Name, gleiche Bytes. Ein Speichern eines Modells, das sich nicht geändert hat, liefert die ursprünglichen Bytes zurück.

Ein Paket, das der Editor selbst erstellt (nicht geladen), hat keine Quelle, die erhalten werden könnte. Es wird aus dem Modell mit den eingebauten Standardformaten geschrieben.

## Unverändert erhalten {#kept-verbatim}

Der Roundtrip-Test [`preservation.test.ts`](../../../../src/core/docx/preservation.test.ts) lädt ein Paket mit diesen Teilen, bearbeitet Text, eine Tabellenzelle und die Kommentare, speichert und prüft, dass jeder Eintrag, den die Bearbeitung nicht betraf, byte-identisch ist (die Eintragsliste bleibt ebenfalls unverändert, abgesehen von einem erzeugten Kommentarteil):

| Erhalten                                                                                                                                                                                                                                | Hinweise                                                                                                                                            |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `customXml/*`-Elemente, ihre Eigenschaften und Beziehungen                                                                                                                                                                              | Nur für ein datengebundenes Steuerelement neu geschrieben, das die Person bearbeitet hat.                                                           |
| `word/glossary/document.xml` und ihre Teile (Bausteine)                                                                                                                                                                                 | Nur gelesen, um den Platzhaltertext von Inhaltssteuerelementen anzuzeigen.                                                                          |
| `word/vbaProject.bin` und der Inhaltstyp für Makros                                                                                                                                                                                     | Bleibt erhalten, wird nie ausgeführt. Die Dateiendung der gespeicherten Datei ist Sache des Hosts.                                                  |
| `word/people.xml`                                                                                                                                                                                                                       | Siehe „Kommentare“ unten.                                                                                                                           |
| `word/fontTable.xml` und eingebettete Schriften (`word/fonts/*.odttf`)                                                                                                                                                                  | Werden nicht zum Rendern verwendet; bleiben mit ihren Beziehungen erhalten.                                                                         |
| `word/settings.xml` (Zoom, `w:extLst`, Kompatibilitäts- und Schutzelemente)                                                                                                                                                             | Nur die Flags, die der Editor verwaltet, werden gepatcht (Änderungsverfolgung, gerade und ungerade Kopfzeilen, Silbentrennung, ...).                |
| `word/theme/theme1.xml`, `word/webSettings.xml`, `docProps/custom.xml`, Vorschaubilder                                                                                                                                                  | Die Bearbeitung des Designs wird abgelehnt (siehe unten).                                                                                           |
| Bilder und andere Medien, die nicht ersetzt werden                                                                                                                                                                                      | Ein Bild, das die Person ersetzt, erhält einen neuen Teil.                                                                                          |
| Unbekannte Teile und Beziehungen jeden Typs                                                                                                                                                                                             | Alles, was das Paket enthält und wofür der Editor keinen Leser hat.                                                                                 |
| In `document.xml`: `mc:AlternateContent`, Erweiterungslisten (`w:extLst`), `w14:`-/`w15:`-Auszeichnungen, `w:tblPrChange`, `w:trPrChange`, `w:tcPrChange`, Lesezeichen, Feldcodes, unbekannte Eigenschaften von Textläufen und Absätzen | In Absätzen und Tabellen, die die Person nicht umstrukturiert hat. Bearbeitete Absätze behalten ihre nicht modellierten Kinder `w:pPr` und `w:rPr`. |

## Kommentare {#comments}

Bearbeitungen von Kommentaren patchen die ursprünglichen Inhalte und Metadaten an ihren Beziehungszielen. Ein unveränderter Kommentar behält seine Absätze, Formatierungen der Textläufe und unbekannte Auszeichnungen. Textänderungen behalten die gestalteten Textläufe, die nicht betroffen sind. Die letzte Absatz-ID und die dauerhafte ID halten Antworten, Erledigt-Status und UTC-Datumsmetadaten über `commentsExtended.xml`, `commentsIds.xml` und `commentsExtensible.xml` hinweg konsistent. Gelöschte Kommentare verlieren ihre Verankerungen und Metadaten; neue Antworten erhalten Verweise in dem Bereich ihres übergeordneten Kommentars. Undurchsichtige Editor-IDs werden konsistent auf dezimale Paket-IDs abgebildet, passend zu ihren Verankerungen im Dokument. Der Teil für Personen bleibt unverändert. Es werden keine Steuerelemente für die Erstellung formatierter Kommentare bereitgestellt.

Die Regressionsabdeckung nutzt ein formatiertes, nativ von Word erstelltes Testbeispiel in `comment-preservation.test.ts`. Prüfungen mit Word 16 zum erneuten Öffnen und Speichern decken das Erledigen, Bearbeiten, Löschen und Hinzufügen von Kommentaren ab, einschließlich Antworten und nicht standardmäßiger Teil-Speicherorte. Sechs Browser-Bindings prüfen gespeicherte Verankerungen von Antworten.

## Modelliert und bearbeitbar {#modeled-and-editable}

Text und Zeichenformatierung, Absatzformatierung und Formatvorlagen (Verwendung und Bearbeitung der Formatierung pro Formatvorlage), Listen und Nummerierungsdefinitionen, Abschnitte und Seiteneinrichtung, Kopf- und Fußbereiche sowie Fußnoten, Felder (bearbeitbare Ergebnisse, Felder aktualisieren), Kommentare und Änderungsverfolgung, Inhaltssteuerelemente und Formularfelder, Tabellen (unten), Hyperlinks und Lesezeichen, Bilder, einfache Formen und Textfelder, SmartArt, klassische Diagramme und zugelassene ChartEx, Dokumenteigenschaften sowie die Bearbeitungseinschränkungen, die Word liest (der Formularschutz wird erzwungen; andere Einschränkungen bleiben erhalten, werden aber nicht erzwungen).

### Tabellen {#tables}

Befehle für Zeilen und Spalten, Verbinden und Teilen sowie das Layout verbundener Zellen werden über die Tabellenstruktur-Engine des Kerns bearbeitet (`ooxml-core/docx`, `table-structure.ts`) und vom verbindungsbewussten Schreiber (`write-table-structure.ts`) geschrieben. Die Engine folgt Word: Ihre Ergebnisse für Zeile einfügen, Spalte einfügen, Zeile löschen, Spalte löschen, Verbinden und Teilen wurden bei kleinen Tabellen mit Word 16 aufgezeichnet (`src/core/docx/__fixtures__/word-table-structure.json`, erstellt durch `src/core/scripts/docx/table-structure-word-probe.ps1`), und ein Test prüft jedes davon.

- Eine Zeile oder Zelle, die eine Bearbeitung überlebt, behält ihr XML-Element. Daher bleiben `tblPr`-, `trPr`- und `tcPr`-Kinder, die das Modell nicht führt, Erweiterungsattribute und die `w14:paraId`-Werte der Zeilen erhalten. Nur `tblGrid`, `gridSpan`, `vMerge`, `tcW`, die Zellen, die eine Bearbeitung erzeugt, und die Zeilen, die hinzugefügt oder entfernt werden, ändern sich.
- Neue Zeilen kopieren die Zeile, aus der sie entstehen (Zelllayout, Höhe, Wiederholung als Kopfzeile); neue Zellen kopieren die Formatierung der Zelle daneben. Das Löschen der ersten Zeile einer vertikalen Verbindung verschiebt die Verbindung in die nächste Zeile und leert deren Text, wie es Word tut.
- Verschachtelte Tabellen werden direkt bearbeitet: Eine Änderung der inneren Tabelle verändert nur das innere `w:tbl`.
- Eine reine Textbearbeitung einer Tabelle schreibt ihre Struktur nie neu.

Abgelehnt (der Befehl ist deaktiviert, und eine Modelländerung, die der Schreiber nicht ausdrücken kann, löst den unten genannten Fehler aus). Jede Ablehnung betrifft eine Tabelle, die Word selbst in etwas verwandelt, das ein einfaches Raster nicht halten kann:

| Bearbeitung                                                                                                                                                                                                                                                                                                                          | Warum                                                                                                                                                                                                            |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Eine Spalte links von einer verbundenen Zelle (einer Zelle, die mehrere Spalten überspannt) oder durch sie hindurch einfügen                                                                                                                                                                                                         | Word fügt Zeilen mit `gridAfter` und eine neue Zelle so breit wie die verbundene Zelle ein.                                                                                                                      |
| Eine Spalte löschen, die eine verbundene Zelle nur teilweise abdeckt                                                                                                                                                                                                                                                                 | Word löscht die ganze verbundene Zelle und lässt die Zeile zu kurz (`gridAfter`).                                                                                                                                |
| Eine Zelle, die mehrere Spalten überspannt, in eine andere Anzahl Spalten teilen oder in mehr Spalten als sie überspannt, wenn sie mehr als eine überspannt                                                                                                                                                                          | Word ordnet die Tabelle neu an. Das Teilen in die eigenen Spalten der Zelle und das Teilen einer einspaltigen Zelle funktionieren.                                                                               |
| Eine vertikale Verbindung in eine andere Zeilenanzahl als ihre Höhe teilen                                                                                                                                                                                                                                                           | Word akzeptiert nur Teiler der Höhe; implementiert ist nur das vollständige Aufheben der Verbindung.                                                                                                             |
| Einen Bereich mit einer Zelle verbinden, die daraus herausragt, oder Zellen mit verschachtelten Tabellen                                                                                                                                                                                                                             | Das Ergebnis würde Inhalt oder die Form der Verbindung verlieren.                                                                                                                                                |
| Jede Strukturbearbeitung einer Tabelle mit Zeilenversätzen (`gridBefore`, `gridAfter`), verfolgten Zeilen- oder Zellenänderungen (`w:ins`, `w:del`, `trPrChange`, `tcPrChange`), `hMerge`, Inhaltssteuerelementen um Zeilen oder Zellen oder Hyperlinks, Feldern, Lesezeichen oder anderer Auszeichnung im Textfluss in ihren Zellen | Die Ladewarnung „Verbundene, verschachtelte oder komplexe Tabellen können gelesen, aber ihre Zeilen- und Spaltenstruktur nicht sicher bearbeitet werden.“ sagt das. Der Text in ihren Zellen bleibt bearbeitbar. |

`saveDocx` wirft `Cannot change the structure of a merged, nested, or complex table. The original
DOCX package remains unchanged.` bei einer Strukturänderung einer solchen Tabelle; das Paket wird nicht verändert.

Tabelleneigenschaften außer den Rändern, die der Dialog „Tabelleneigenschaften“ bearbeitet (Breite, Ausrichtung, Einzug, Rahmen, Formatvorlage, Darstellung), werden dargestellt und erhalten, sind aber nicht bearbeitbar: Eine Änderung dieser Werte im Modell löst `Cannot edit table grid widths, width, alignment, indent, borders, or style; ...` aus.

## Abgelehnt mit einer Diagnose {#refused-with-a-diagnostic}

Beim Speichern wirft der Editor einen Fehler, der den Grund nennt und das Quellpaket unberührt lässt, wenn das Modell:

- den Katalog der Absatz-, Zeichen- oder Tabellenformatvorlagen bearbeitet (`Editing the paragraph style catalog is not supported; source styles.xml is preserved unchanged.`, sowie die Varianten für Zeichen und Tabellen), abgesehen von der Formatierung pro Formatvorlage, die der Editor verwaltet;
- das Design bearbeitet (`Editing the theme catalog is not supported; source theme1.xml/settings.xml are preserved unchanged.`);
- eine Block- oder Absatz-ID wiederholt (`Duplicate document block id` / `Duplicate document node id`);
- ein Bild, einen Hyperlink, eine Form oder ein Diagramm verlangt, das eine Beziehung braucht, die der Aufrufer nicht zuweisen kann;
- die Modellprüfung nicht besteht (`assertValidDocumentModel`: zum Beispiel ein Dokument ohne Abschnitt).

Das Laden ist auf 50 MB pro Paket, 5.000 Einträge und 200 MB entpackt begrenzt (`DOCX_ZIP_LIMITS`). Ein Paket, das eine Grenze überschreitet, wird abgelehnt, bevor ein Teil gelesen wird.

## Beim Laden gemeldet, durch ein Speichern nicht verändert {#reported-at-load-not-changed-by-a-save}

`model.warnings` führt Funktionen auf, die geladen werden, aber nicht wie in Word dargestellt oder bearbeitet werden, zum Beispiel eingebettete OLE-Objekte (bleiben erhalten, werden als Platzhalter gezeichnet), komplexe `HYPERLINK`-Felder (bleiben als Feldcodes erhalten), Änderungsverfolgung in Tabellenstrukturen (bleibt im XML, nicht im Modell), Bildaufzählungszeichen und manche mit Formatvorlagen verknüpfte Nummerierung sowie Bearbeitungseinschränkungen, die erhalten, aber nicht erzwungen werden.

## Grenzen der Garantie {#known-limits-of-the-guarantee}

- **Auszeichnungen im Textfluss von Tabellenzellen** blockieren strukturelle Bearbeitungen dieser Tabelle (siehe oben), aber nicht Textbearbeitungen.
- **Das Layout ist keine erhaltene Information.** Zwischengespeicherte Seitenumbruch-Hinweise (`w:lastRenderedPageBreak`) in bearbeiteten Absätzen werden verworfen; Word berechnet sie neu.
- Inhalt in einem Teil, für den der Editor keinen Leser hat, bleibt erhalten, wird aber nicht geprüft. Ein beschädigter Teil bleibt beschädigt.
