# Word reference corpus and verification

This page records the checked-in corpus of Word-authored documents, what is compared against it
and the current results. It is evidence for the listed cases only. It is not a claim of Word
parity, and it does not certify glyph metrics, fonts other than the one used, or Microsoft 365
subscription behaviour.

## What is in the corpus

`src/core/docx/__fixtures__/word-corpus/` holds twelve small documents authored by desktop Word
through COM (`Word.Application`), generated by `src/core/scripts/docx-word-corpus.ps1`. Recorded
with Word build `16.0.20527`, US Letter, 1 inch margins. Every body and heading style is set to
Courier New, whose advance is 0.6 em, so a headless test can measure text exactly. That makes the
comparison one of line breaking and pagination, not of font metrics.

| Document                | Features                                                                 |
| ----------------------- | ------------------------------------------------------------------------ |
| `01-headings-styles`    | Title, headings, bold, italic, alignment, indents, exact line spacing    |
| `02-lists-numbering`    | Bullets, numbered list, multilevel outline                               |
| `03-tables-merged`      | Table with horizontally and vertically merged cells, header row, shading |
| `04-header-footer`      | Header text, footer with PAGE field, two pages                           |
| `05-footnotes-endnotes` | Two footnotes (one wrapping) and one endnote                             |
| `06-sections-columns`   | Portrait, landscape and two-column sections (three pages)                |
| `07-images`             | Inline picture and a square-wrapped floating picture                     |
| `08-equation`           | Two OMML equations (fraction and root, summation)                        |
| `09-fields-toc`         | Table of contents, heading page breaks, date field                       |
| `10-tracked-comments`   | Tracked insertion, deletion and replacement, one comment                 |
| `11-content-controls`   | Text, drop-down and check-box content controls                           |
| `12-chart`              | Inline Word chart (default clustered column)                             |

Each document has `<name>.docx`, `<name>.facts.json` and `<name>-p<N>.png` per page (about 50 DPI,
rendered from `Pages(N).EnhMetaFileBits`). The folder is about 0.55 MB. The facts file records the
Word build, page count, line count, per-paragraph start page, position and the character offset at
which each line starts (scanned with `Range.Information`), floating shape geometry, section
setup and counts of notes, comments, revisions and tables.

## Regenerating

```
pwsh -File src/core/scripts/docx-word-corpus.ps1
```

Needs desktop Word on Windows. The script waits up to 15 minutes for a running `WINWORD.EXE`,
always quits Word in a `finally` block, and overwrites the folder. Review the diff of the facts
before committing: a different Word build or printer driver can legitimately move line breaks.

## Comparison test

`src/core/docx/word-corpus.test.ts` loads each `.docx` with `loadDocx`, lays it out with
`layoutDocumentModel` and a monospace measurer (0.6 em per character), and compares with the
facts:

- page count: exact;
- each non-table paragraph's start page: exact;
- each paragraph's line count and line-start offsets: exact (monospace text leaves no rounding
  room, so any tolerance would hide a real difference).

Not compared: vertical positions (the line-height model is not Word's), paragraphs inside tables
(Word's end-of-cell marks make the numbering differ), paragraphs with no letters (equation-only
paragraphs, whose text Word linearises), and floating-object geometry.

Paragraphs are matched by their first eight letters in document order, so list labels, note marks
and field results do not matter. Differences that are real layout gaps are named in
`acceptedGaps` in the test (id, document, paragraph, reason). The test fails if an accepted gap
starts to pass, so the entry has to be removed when the gap is fixed.

### Raster comparison

The core has no headless rasteriser, so the PNG pages are not compared in `src/core`. They are the
reference images for the browser suite (`e2e/docx`) and for manual inspection; a pixel comparison
needs a recorded browser and font version, as the roadmap requires.

### Current results

Eight of twelve documents match Word on every compared fact. Accepted gaps:

| Id                                   | Document              | Paragraph | Difference                                                             |
| ------------------------------------ | --------------------- | --------- | ---------------------------------------------------------------------- |
| `bold-justified-indented-first-line` | `01-headings-styles`  | 5         | First line breaks at 56 characters, Word 64; cause not isolated        |
| `two-column-section-line-count`      | `06-sections-columns` | 10        | 45 lines against Word 39 in the two-column section                     |
| `wrapped-float-line-count`           | `07-images`           | 3         | 13 lines against 12 beside a square-wrapped picture                    |
| `heading-first-line-offset`          | `07-images`           | 1         | Heading line starts at offset 1, Word 0                                |
| `toc-field-line-start`               | `09-fields-toc`       | 2         | Table-of-contents paragraph starts at offset 3, Word 0 (field offsets) |

Page counts match Word for all twelve documents.

## Reopen check

`src/core/scripts/docx-word-corpus-reopen.ps1` (a step of `node scripts/office-acceptance.mjs word`)
loads each corpus document with the core, appends a marker word to the first plain paragraph, saves
with `saveDocx`, reopens the result in Word and fails on a thrown open, a "Repaired" caption, a
missing marker, or a page count more than one page from Word's original. Last run: all twelve
documents reopen without repair, with the marker present and the same page count as the original.
This shows Word opens the saved packages; it does not show that unrelated parts are unchanged.
