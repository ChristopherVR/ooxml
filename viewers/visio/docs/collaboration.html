Collaboration

File > Share starts a live session between windows of one browser. Sharing across devices is not available yet.

Partial, same-browser only

There is no hosted service and no server transport in this build. Nothing leaves your browser, and no document is uploaded.

What exists today

  • A live session built on ooxml-core/collab (Yjs) over a BroadcastChannel, so windows and tabs of the same browser can share a drawing.
  • The whole VSDX package is shared, and the collab runtime loads only when sharing starts.
  • Remote changes arrive as one undoable history step, and collaborators appear through the shared presence element.
  • The session name is 1 to 64 letters, digits, hyphens or underscores. A window joining a session whose room already holds a drawing adopts it; otherwise it seeds the room.

Try it

  1. Open the playground in two windows or tabs.
  2. Open the sample drawing in one window.
  3. In both windows choose File, then Share, enter the same session name and start sharing.
  4. Edit shape text in one window and watch the other follow. Undo reverts the remote step.

What is not supported

Area Status
Sharing across devices Needs a host-provided server transport; none ships with this build
Merging concurrent edits Whole-package sharing: concurrent changes are not merged field by field, the last package wins
Comments, authentication and roles Not implemented
Embedding API for custom transports Not documented here; File > Share is the supported entry point

The evidence is recorded in the capability ledger under “Collaboration and comments”.
