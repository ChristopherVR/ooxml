# Publication

Les paquets Visio sont publiés par le flux propre au dépôt `ooxml`, décrit dans `docs/releasing.md` du dépôt : le script racine `scripts/release-plan.mjs` attribue à chaque paquet son numéro de version à partir des commits conventionnels depuis son dernier tag `<npm-name>@<version>`, et le workflow racine `.github/workflows/release.yml` pose les tags, rédige les journaux de modifications et publie avec la publication de confiance de npm (OIDC et provenance, sans jeton). La table des paquets Visio est `viewer('visio', ...)` dans le script racine `scripts/viewer-packages.mjs` (`viewers/visio/scripts/viewer-packages.mjs` en est une vue pour les scripts de construction). Le dossier `.github/` de ce visualiseur est inopérant.

Huit paquets sont livrés : `visio-core` et `visio-{react,vue,angular,svelte,solid,vanilla}-viewer` à partir de `packages/{core,react,vue,angular,svelte,solid,vanilla}`, et `visio-viewer-mcp` à partir de `mcp`. Une modification de `src/` ou de `packages/bindings/src/` ici, ou de `scripts/build-packages.mjs` ou `tsconfig.build.json`, publie les six paquets de visualiseur ; une modification dans le dossier propre à un paquet ne publie que ce paquet. L'implémentation du visualiseur elle-même est `ooxml-ui/visio` (`src/ui/src/visio`), publiée avec `ooxml-ui`, et les paquets dépendent de `ooxml-core` et `ooxml-ui` par une plage d'espace de travail : le flux de publication réécrit chacune en plage caret sur la version publiée avec eux. Les modifications de documentation et de tests seuls ne publient pas de paquets, sauf si elles modifient le README d'un paquet livré.

`bun run check` dans `viewers/visio` vérifie les sources, les adaptateurs, la documentation, les constructions et les consommateurs empaquetés face au cœur et à l'interface publiés dans le registre (`bun run test:packages`). La CI exécute les consommateurs empaquetés avec `--workspace-runtime` (`bun run test:packages:workspace`), en empaquetant les `ooxml-core` et `ooxml-ui` de cette copie de travail tels qu'une publication les livrerait ensemble, et `bun run test:browser` vérifie le comportement dans le navigateur et se termine par la même vérification des paquets empaquetés dans un navigateur (`test-packages-browser.mjs --workspace-runtime`). La construction inclut les deux workers de navigateur, émet les déclarations TypeScript et fournit la source Svelte native ainsi que les points d'entrée serveur de Solid et Svelte.

Ne lancez jamais `npm publish` ni ne poussez de tags de publication à la main. Une publication échouée est relancée via l'entrée `tag` du workflow de publication, qui ignore les versions déjà présentes sur npm.

La provenance des outils de publication est consignée dans `scripts/RELEASE-PROVENANCE.md`.
