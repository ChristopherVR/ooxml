# Publicación

Los paquetes de Visio se publican mediante el flujo propio del repositorio `ooxml`, descrito en `docs/releasing.md` del repositorio: `scripts/release-plan.mjs` de la raíz asigna la versión de cada paquete a partir de los commits convencionales desde su última etiqueta `<npm-name>@<version>`, y `.github/workflows/release.yml` de la raíz crea las etiquetas, escribe los registros de cambios y publica mediante la publicación confiable de npm (OIDC y procedencia, sin token). La tabla de paquetes de Visio es `viewer('visio', ...)` en `scripts/viewer-packages.mjs` de la raíz (`viewers/visio/scripts/viewer-packages.mjs` es una vista de ella para los scripts de compilación). La carpeta `.github/` de este visor no tiene efecto.

Se publican ocho paquetes: `visio-core` y `visio-{react,vue,angular,svelte,solid,vanilla}-viewer` desde `packages/{core,react,vue,angular,svelte,solid,vanilla}`, y `visio-viewer-mcp` desde `mcp`. Un cambio en `src/` o en `packages/bindings/src/` de este directorio, o en `scripts/build-packages.mjs` o `tsconfig.build.json`, publica los seis paquetes de visor; un cambio en el directorio propio de un paquete publica ese paquete. La implementación del visor en sí es `ooxml-ui/visio` (`src/ui/src/visio`), que se publica con `ooxml-ui`, y los paquetes dependen de `ooxml-core` y `ooxml-ui` mediante un rango de espacio de trabajo: el flujo de publicación reescribe cada uno como un rango con circunflejo sobre la versión publicada junto con ellos. Los cambios solo de documentación y de pruebas no publican paquetes, salvo que modifiquen el README de un paquete distribuido.

`bun run check` en `viewers/visio` verifica el código fuente, los adaptadores, la documentación, las compilaciones y los consumidores empaquetados frente al `ooxml-core` y el `ooxml-ui` del registro (`bun run test:packages`). La CI ejecuta los consumidores empaquetados con `--workspace-runtime` (`bun run test:packages:workspace`), empaquetando el `ooxml-core` y el `ooxml-ui` de esta copia de trabajo tal como los publicaría un lanzamiento conjunto, y `bun run test:browser` verifica el comportamiento en el navegador y termina con la misma comprobación de paquetes empaquetados en un navegador (`test-packages-browser.mjs --workspace-runtime`). La compilación incluye ambos workers del navegador, emite las declaraciones de TypeScript y suministra el código fuente nativo de Svelte y los puntos de entrada de servidor de Solid y Svelte.

Nunca ejecute `npm publish` ni envíe etiquetas de publicación a mano. Una publicación fallida se reintenta mediante la entrada `tag` del flujo de publicación, que omite las versiones que ya están en npm.

La procedencia de las herramientas de publicación se registra en `scripts/RELEASE-PROVENANCE.md`.
