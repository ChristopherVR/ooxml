## Done

- **Shared areas:** `xml`, `opc`, `units`, `color`, `geometry`, `drawingml`, `diagram` (SmartArt), `chart` (model, parser, writer and SVG painter), `digest`, `crypto` (package encryption), `math`, `text`, `i18n`, `ribbon`, `collab` (Yjs real-time collaboration), `teams`, `automation` and `embedding`. `AGENTS.md` has the authoritative list.
- **Formats as areas:** `docx`, `xlsx`, `pptx` and `visio`, each with its own parser and writer (Visio edits are bounded, and legacy `.vsd` is preview only).
- **Products:** the PowerPoint, Word, Excel, Visio and OpenTeams viewers and the shared `ooxml-ui` elements live in this repository and are released from one pipeline.
- **PowerPoint viewer moved in (2026-11-16):** pptx-viewer lives in `viewers/pptx` with its history and release tags, its demos and browser tests are at `demos/pptx/` and `e2e/pptx/`, and CI verifies it like the other viewers. With no outside repository consuming this one, the sync workflow, the local-linking script and the fleet report are retired.
- **Wave 6 (2026-10-23):** one binding kit in `ooxml-ui/bindings`, pptx headless controllers, and chart and SmartArt editing shared across products. Word and Excel insert and edit SmartArt; Word, Excel and Visio edit charts; pptx saves classic chart title, legend, axis and series edits and ChartEx title, legend, label and series edits through the neutral writers. Details are in [structure-plan.md](structure-plan.md) section 5 and [agnostic-core-plan.md](agnostic-core-plan.md).
- **Shared Office delivery (2026-10-27):** source-backed chart admission and saves, interpreted Word/Excel SmartArt previews and generated 2D caches, shared SmartArt style/colour galleries, DrawingML outlines/effects/format schemes, advanced shared chart controls, and Word/Excel ChartEx editing. PowerPoint's admitted classic and ChartEx save families and shared model projections have corpus, browser and native reopen evidence. The [delivery ledger](office-shared-parity-delivery.md) records tested cases and remaining boundaries.

## Next

- **Finish the DrawingML consumer migration:** shared outlines, typed effect lists, theme format schemes with `phClr` substitution and pattern/picture fill codecs are implemented. The pptx colour codec (all 26 transforms, preset and system colours), the theme part reader, the format scheme reader, `fillRef`/`lnRef`/`effectRef` resolution with `phClr`, the master `p:clrMap` reader and the theme writer now run on the shared resolver, `parseTheme`, `parseThemeFormatScheme`, the `resolveTheme*Style` resolvers and `drawingThemeXml`, pinned by corpus parity harnesses (2026-11-16); colour opacity and the UI's colour-choice reader use the resolver's alpha and the core reader, the gradient and effect-list codecs read through the shared readers, and effect DAGs run on a shared model and interpretation (sibling composition, masks, blends and transforms are still approximated). The pptx paragraph property readers and writers (attributes, spacing, bullet size, font and type, tab stops, so list-style levels too) run on the shared paragraph codec, pinned by a read and save parity harness over 54,742 corpus elements, and so do the run property attributes, font slots and run `a:rtl` (80,232 elements) and the `a:bodyPr` attributes, autofit and text warp (26,999 elements); run effects, gradients, outlines, table cell anchors and the SmartArt drawing text style read through the shared effect, gradient, line and text readers (2026-11-16). Still to move: the pptx object-tree writers of run effects, fills and outlines onto the shared writers; painting the approximated DAG members remains open. The order is in [agnostic-core-plan.md](agnostic-core-plan.md) step 3.
- **One XML model:** the `pptx` area still uses its own XML object model and is compiled with relaxed TypeScript flags while it is migrated onto the shared `xml` area and tightened. New code is strict. The whole model now compiles strict: `pptx/core`, `pptx/converter`, `pptx/cli`, `pptx/editor/ai` and `pptx/editor/loader` joined `pptx/ui`, `pptx/node` and `pptx/signature-node` (2026-11-16). Still relaxed: `pptx/editor/render` (70 source errors), `pptx/automation` (15), the `pptx/__tests__` integration suite and 197 other test files listed by name; about 3,150 strict errors in all, almost all in tests. The measured per-directory inventory and what blocks moving the trees onto `xml` are in [agnostic-core-plan.md](agnostic-core-plan.md) section 3.9.

The presentation controllers (rehearsal timers, ink and the presenter window), the Fill inspector section and the pptx tab row on `office-ui-ribbon` (`pptx-ui-ribbon-tabs`) are now shared in every binding (2026-11-16). Next: the remaining inspector sections and per-binding state machines, onto headless controllers in `ooxml-ui/pptx` with one store adapter per framework and native templates on top. See [structure-plan.md](structure-plan.md) section 5.
