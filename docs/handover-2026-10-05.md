# Handover: moving all UI and logic into `ooxml`

State as of 2026-10-05, about 17:00 local time.

## Direction

- The `ooxml` repository is the single home for Office logic and UI.
- It has two destinations:
  - **`ooxml-core`:** all logic, plus DOM-free UI logic under `src/<area>/ui`.
  - **`ooxml-ui`:** the editor and viewer custom elements, as the subpaths `ooxml-ui/xlsx`, `/docx`, `/visio` and `/teams`.
- The docx, xlsx, visio, teams and pptx viewer repositories keep only framework bindings, demos, e2e tests and docs.
- Everything goes straight to `main`: no feature branches and no pull requests.
- Toolchain target: latest dependencies and TypeScript, with oxlint and oxfmt and no eslint. Vite+ was not adopted (see "Decisions").

## Published and current

- `ooxml-core` **0.20.0** and `ooxml-ui` **0.28.0** are on npm. They contain the four editor subpaths and the `src/{xlsx,docx,visio}/ui` modules.
- Later commits are not published yet: `0ea4098` (exports `demoDocument` from `ooxml-ui/visio`) and the chore commits after it. The next `feat` commit releases a new `ooxml-ui` minor.
- To release, run `gh workflow run release.yml -R ChristopherVR/ooxml`. The auto-mode classifier blocked the assistant from dispatching it, so the user ran it last time. The hourly schedule is unreliable.

## Decisions made (revisit if you disagree)

- **Vite+ not adopted.** It pins older `vitest`, `oxfmt` and `oxlint` than the latest releases and aliases `vite`. The repos use the individual latest packages instead.
- **TypeScript:** 6.0 where Angular, Svelte or Vue type checking is involved, 7 elsewhere.
- **Lint:** oxlint with a lean config (correctness as errors, suspicious as warnings, no style rules), run in a core CI job.
- **Product editors in `packages/ui`:** these are imperative custom elements, not Lit classes, and keep their own `?raw` CSS. `AGENTS.md` says so.

## Gotchas

- Windows with autocrlf: many files show as modified because of CRLF. Check `git diff --ignore-cr-at-eol` before trusting `git status`.
- Do not run `oxfmt` with broad globs. Pass explicit files.
- Releases are workflow-only. Never run `npm publish` or push tags by hand.
- `scripts/link-local.mjs` rewrites manifests to `file:` ranges, which `check:published` rejects. Always run it with `--restore` before committing.
