# Native inserted date-field cache acceptance

The original source drawing is generated by an owned invisible Visio 16 instance,
with one local rectangle and `Created: ` text. It contains no copied user document.
The acceptance script adds `DOCCREATION()` fields using core, then opens, resaves
and reopens every result in native Visio. Recorded native displays cover short,
ISO, long, time and combined date/time pictures in Australia/Brisbane. Document
properties are UTC timestamps; their display uses the current viewer's wall-clock
zone, so time strings are native host evidence rather than timezone-independent
CI expectations.

Before the repair, core wrote a numeric serial cache with `U="DATE"` and an
untyped Format cache. Core displayed the expected date but native Visio displayed
`0`. The repaired writer emits a timezone-free ISO DATE cache and a `U="STR"`
format cache, retaining field formulas. All five native displays now match core
and survive native save/reopen. Unit regressions verify native cache syntax,
string format typing, source properties and core reopen.

Regenerate after `bun run build:visio`:

```powershell
./scripts/visio-date-field-write-acceptance.ps1 -OutputDirectory "$env:TEMP/visio-date-fields"
```

The script writes its native result with the host timezone. Other date functions,
locale calendars, custom shape formula fields and general field-editing parity
remain separate evidence scopes. Microsoft documents [date format pictures](https://learn.microsoft.com/en-us/office/client-developer/visio/about-format-pictures)
and [field data types](https://learn.microsoft.com/en-us/office/client-developer/visio/type-cell-text-fields-section).
