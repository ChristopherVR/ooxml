# Native tables before continuous sections

Generated by `scripts/record-word-continuous-tables.ps1` in a separate hidden Word
instance using fresh synthetic documents. Word build: `16.0.20430.20140` (COM:
`16.0.20430`). Installed licenses are Professional 2021/ProPlus 2024; these are
desktop Word measurements, not a current M365 subscription certification.

The first cases contain four, five or 120 rows in a one-cell table, followed by a
continuous section break and two body paragraphs. The first section has two
columns, the second one. Table rows have exact 12 pt height and cannot split.
Table width: 216 pt; cell padding and borders: zero. Arial 12 pt, exact 12 pt
line spacing; 612 by 792 pt pages with 72 pt margins.

Word balances the final page's table rows between columns. The mandatory empty
paragraph after the table adds a line after balancing. An even row count thus
leaves the final column one line taller; with five rows, the marker fills the
shorter column. Earlier pages retain their full height.

Three more cases cover a splittable row with six lines followed by a two-line
row, and repeated headers on one and two pages. The multiline rows use minimum
12 pt height. Word splits the first row after four lines and balances the total
eight lines across columns. The header cases repeat `Row1` in every column,
including both columns on the second page. Original header range positions and
visible PDF repeat counts are separate measurements; run
`scripts/record-word-table-headers.py` with pypdf after the PowerShell recorder
to add `headerCounts` to the evidence.

The structured evidence records every paragraph's physical page and origin.
DOCX sources and JSON are committed; diagnostic PDFs remain outside the repo.
Core and six-framework browser tests compare nonempty row and body paragraph
origins and repeat counts. These cases do not certify glyph metrics, borders,
all row-splitting configurations, nested tables, merges, floats or footnotes.
