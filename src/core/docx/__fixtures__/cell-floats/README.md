# Floating objects in table cells and floating charts

`cases.ts` builds every document; `src/core/scripts/docx-word-cell-float-probe.ps1` writes them with `docx-word-cell-float-cases.ts`, opens each in an owned, invisible Microsoft Word 16.0.20527 through its documented COM object model (OpenAndRepair off, so a package Word would repair fails), exports it to PDF and closes it without saving, and `docx-word-cell-float-pdf.py` (PyMuPDF) reads the PDFs into `word-positions.json`: per case, in points from the page's top-left, the object's rectangle (the red shape, or the green chart area of a chart), the table's horizontal rules and the words the tests read (`[text, x, y, end x]`). No user documents are opened. The tests build the same packages from `cases.ts`, so no `.docx` is kept here; `e2e/docx/support/cell-floats-demo.docx` is the demonstration document (`cellFloatDemo`), which Word opens the same way.

Each case is Courier New 11 pt on a Letter page with margins left 1.5 in, right 1 in, top 1 in and bottom 1.5 in, in compatibility mode 15 unless its name starts with `m14-`: three short paragraphs, a fixed two-column table (tblInd 720, 3600-twip columns, 108-twip cell margins, single borders) whose second cell of the first row holds "First" and the anchor paragraph, then a long paragraph. `h-*` cases vary `wp:positionH` (offset 18 pt or an alignment) with the vertical frame `paragraph:9pt`, `v-*` cases vary `wp:positionV` with `column:18pt`, each with square wrapping and with none; `*-lic0-*` cases write `layoutInCell="0"`; `wrap-*` cases put a 36 pt square at the cell text's start (or aligned right) beside a long anchor text; `grow-*` cases put a 54 pt tall object 30 pt below its paragraph; `chart-*` cases float the chart of `../chart.docx` in the body and in a cell.

Observed:

- From mode 15 an object anchored in a cell is laid out in it whatever `layoutInCell` says. In mode 14 `layoutInCell="0"` places it on the page with the page's frames, its paragraph frame being the row's top (and a wrapping one over the text column pushes the table below it), while `"1"` lays it out in the cell.
- In the cell, `column`, `margin` and `character` measure from the cell's text area (the character frame from the left edge of the character before the anchor, as in the body), `page`, `leftMargin` and `insideMargin` from the cell's left edge, `rightMargin` and `outsideMargin` from the text area's right edge; alignments use the text area (`page` aligns the same way). `paragraph` and `line` are the anchor paragraph and line; every other vertical frame is the cell from its top. An object never starts above the cell's top, and a wrapping object is kept between the cell's edges (a `rightMargin` square moves left to end at the cell's edge).
- Square, tight and top-and-bottom objects wrap the cell's text as they wrap body text (on the larger side, or on both when there is room) and the row grows to the object's bottom; in front of and behind text they do neither.
- A floating chart is positioned and wraps the body text exactly like a floating picture of its size.
