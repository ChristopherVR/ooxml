# Native two-row nested table fragments

Generated by `scripts/generate-word-nested-multi-row.py` from the committed native
ordinary enclosing-border fixture. `scripts/record-word-nested-multi-row.ps1`
uses one owned Word.Application instance, synthetic files only, and records native
Word version/build, page counts, PDF-point text baselines, fills and red inner
border rectangles. Black enclosing borders distinguish the two geometries.

Five profiles contain two automatic, top-aligned inner rows, two direct paragraph
cells per row, complete consistent solid edges, then direct enclosing-cell text.
There are no note references, vertical merges, fixed heights, repeated headers,
paragraph keeping or explicit page breaks. Long parallel stories cover cuts in
the first row, the second row, and both rows over three pages. All per-page body
line sets match the shared core layout.

Native Word repeats the source table outer top (2 points) and bottom (0.5 points)
on every physical inner frame. Interior shared edges are 1.5 points. Previously,
clipping retained an interior edge at some physical cuts and continuation starts,
causing a wrong stroke and roughly 0.5 to 1 point of frame/ink displacement.
The bounded correction retains source outer edges and reflows continuation tokens
through the existing cell/row layout. Frame heights now match within 0.2 PDF
points, widths within 0.1 point; relative ink/frame baselines use a 0.15 point
native rounding tolerance and a 9.6 point reference ascent for these 10 point
Times New Roman probes. These comparisons do not establish glyph/raster parity.

No-op exports preserve every package entry and exact source document XML/model.
Direct enclosing text edits preserve the nested source table XML and other parts.
Complex nested stories, note-bearing two-row tables, keeping, merged cells and
repeated inner headers remain outside this profile; their existing admission and
structural edit guards are unchanged.

With `-VerifyCore`, the recorder evaluates ten core exports (five no-op and five
direct-text edits), each through native open, save and reopen. All twenty page
count and edited/direct-text checks pass. The source fixtures remain immutable
after the frozen commit; regeneration writes to a separate temporary directory.

Validation: 1,462 Word core tests, 36 focused shared DOM tests, and sixteen
repeated browser workflows (ten two-row cases plus six existing nested-note
controls) pass. Strict core and full shared UI types, focused browser-spec types,
source build, lint and targeted formatting pass. The browser checks native frame
heights and relative projected ink positions; glyph/raster equivalence is not
claimed. The profile guard rejects keeping, notes, fixed heights, inner headers,
center alignment, unresolved table widths, inconsistent/merged edges, extra rows and deeper/multiple tables.
Unmeasured multi-row cut profiles emit an explicit approximation diagnostic.
