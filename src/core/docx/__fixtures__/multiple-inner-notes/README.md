# Multiple interacting nested footnotes

`generate-word-multi-note-stories.py` derives ten synthetic documents from the previously recorded `ordinary-table-borders/enclosing-border-split.docx`. It creates two or three distinct footnotes with three explicit lines each, inserts their markers into inner or neighboring enclosing-cell stories, and extends the body stories to twenty or thirty explicit lines. `record-word-multi-note-stories.ps1` opens only these inputs in an owned Word 16 application, saves DOCX and exports PDF. `measure-word-table-borders.py` records physical border bands, body ink and every note line in PDF points.

Native Word removes a story's constraint after its marker is placed. A deferred marker stops only its own story immediately before its line. For example, `multi-note-consumed-inner` has inner body counts 13/13 on page one with the first note, 17/15 on page two without notes, and 0/2 on page three with the second note. `multi-note-consumed-three` uses page-two cuts 17/15 inside and 16 in the neighboring enclosing cell, then 0/2 plus 1 on page three with the two remaining notes. The planner uses currently unplaced references and preserves independent complete prefixes, then reflows the source through the shared geometry.

The measured admission remains a single automatic, top-aligned inner row without deeper tables, repeated headers, paragraph keeping or fixed-height alignment. The complete enclosing row is capped at three distinct anchored references. Reused IDs, multiple unanchored notes, four references, complex inner row structures and long interacting note-body continuations require further native evidence. No font raster parity is claimed. Existing exact-row partial glyph clipping and structural editing guards are preserved.

Regression checks compare every page's body and note markers, all body and note line baselines and physical bands within 0.2 pt, plus exact document/footnote XML and saved/reopened source models. Committed fixture hashes are recorded in the handoff manifest.
