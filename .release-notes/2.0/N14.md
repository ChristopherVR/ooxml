## Added

- `ooxml-core/visio` opens pages of up to about 10,000 shapes. The default XML limits are now 1,250,000 nodes per part and 2,000,000 per package. The ten-second load deadline is unchanged.
- `ooxml-core/visio` package limits gain `maxXmlHeapBytes` (600 MiB by default) and `maxXmlHeapPerInputByte` (4,096), which bound the memory the parsed XML of a drawing may take.
- `ooxml-ui/pptx` exports the scroll window every binding's thumbnail rail uses: `createVirtualWindow`, `createDeferredRows`, `sameRenderedWindow`, `railHasFocus`, `focusCurrentRow` and their constants.

## Changed

- `ooxml-ui` and the Visio viewer packages: the Visio viewer's `zoom-change` event fires once per zoom gesture instead of once per wheel step, when the zoom is applied: 300 ms after the last input, when the gesture ends, or before a pointer press or scroll. Until then the `zoom` property still reads the zoom the gesture started from.
- `ooxml-ui`: Word's SmartArt Design colour and style galleries load the built-in SmartArt definitions (about 390 KB compressed) when a SmartArt is selected, not when the editor opens.

## Fixed

- `ooxml-core` and `ooxml-ui`: a Visio drawing that is too large to open says how many shapes its page has, in the viewer's language.
- `ooxml-ui`: `office-ui-tab-strip` no longer scrolls to its selected tab on updates that change neither the selection nor the tabs.
- The PowerPoint viewers: paging through slides with the keyboard while the thumbnail rail has focus keeps focus on the current slide's thumbnail, as PowerPoint does. Before, focus was lost once the first thumbnail scrolled out of the rail, and in the Vue, Svelte and vanilla viewers the keys then scrolled the rail instead of changing the slide.
- The PowerPoint viewers in all five bindings: undoing or redoing a New Slide while the thumbnail rail has focus keeps focus on the current thumbnail, so Ctrl+Y and the other shortcuts keep working. The vanilla viewer also keeps it when the rail is redrawn.
- The Visio viewer: pressing a selection or rotation handle while a zoom is still previewing starts the drag, and the rotation handle moves with the previewed drawing.

## Security

- `ooxml-core/visio` estimates the memory each XML part will take before parsing it and refuses a drawing that would exceed its budget, with the code `LIMIT_XML_MEMORY` and a message, in the viewer's language, saying how much memory it would need. Past 64 MiB a drawing may take at most 4,096 bytes of memory for each byte of its file, so a small file can no longer expand into a large heap: a 48 KB file of dense XML is refused in about 0.2 s.

## Performance

- The PowerPoint slide thumbnail rail in `pptx-react-viewer`, `pptx-vue-viewer`, `pptx-svelte-viewer`, `pptx-angular-viewer` and `pptx-vanilla-viewer` reads scrolling once per frame and keeps the thumbnails that stay in view. In a deck of 50 or more slides, thumbnails that scroll into view are drawn once scrolling pauses, one per frame, so the rail scrolls at full frame rate. Moving to another slide no longer redraws the visible thumbnails.
- In `pptx-react-viewer`, moving to another slide no longer copies and compares the whole deck for the undo history.
- Zooming a Visio drawing with Ctrl+wheel, a pinch, the zoom slider or the + and - keys scales the drawing smoothly and renders the page once when you stop. The end zoom and scroll position are unchanged.
- The Office suite's home and product landing pages no longer download the Teams engine or the package tools, so they load about 54 KB of compressed JavaScript instead of about 500 KB.
- Creating a new Word, Excel or Visio file in the suite no longer downloads the automation bundle (about 860 KB compressed).
- The suite's styles arrive as one content-hashed stylesheet instead of a chain of thirteen, so the first screen paints sooner.

## Accessibility

- The PowerPoint viewers in all five bindings: when the thumbnail rail shows only the rows in view (a deck of 50 or more slides without sections), each row gives its position and the slide count (`aria-posinset`, `aria-setsize`), so screen readers announce where it sits in the deck.
