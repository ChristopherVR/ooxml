## Breaking

- `ooxml-ui/pptx`: `mapInlineEditorChord` returns a new result, `tab`, for Tab pressed in an inline text editor (and `suppress` for Shift+Tab). Code that switches over every `InlineEditorChord` needs a case for it, and code that treated any result other than `suppress` as "leave the edit" now has to type the tab instead.

## Migration

- `ooxml-ui/pptx`: handle `tab` by calling `insertInlineEditorText(document, '\t')` and keeping the edit open. See the migration guide.

## Added

- `ooxml-ui/pptx`: `listenForPopupMenuDismiss` closes a drop-down menu on Escape wherever focus is and returns focus to the button that opened it, and `insertInlineEditorText` types text at the caret of an inline text editor through the browser's undoable input path.
- `ooxml-core/chart`, `ooxml-core/xlsx`: `chartAccessibleName`, `chartDataDescription` and `ChartSvgOptions.altText`, so a painted chart carries the author's alt text as its title and a short readout of its data as its description. `ChartObject.description` in `ooxml-core/xlsx` holds a chart's alt text.
- `ooxml-ui`: the `--office-ring-on-accent` token, the focus ring colour on accent-filled controls. It follows `--office-accent-foreground` unless a host sets it.

## Changed

- `ooxml-ui/docx`, `ooxml-ui/xlsx`: the arrow half of a split button (Font Color, Highlight, Borders, Fill Color, Underline, Merge & Center and the others) is now a 24 pixel target. Its visible part is unchanged; the extra space after it is clickable, so the controls that follow it sit 10 pixels further along the ribbon row.

## Fixed

- PowerPoint viewers: Tab in a text box types a tab character, as in PowerPoint, instead of moving focus to the format pane, and Shift+Tab keeps the caret in the text box, in every binding. Tab at the start of a bulleted paragraph does not yet change its list level.
- PowerPoint viewers: Escape closes the More actions and Presentation options menus and returns focus to the button that opened them, in every binding. Before, the Svelte and vanilla menus stayed open on Escape, and the others did not return focus.
- PowerPoint viewers: in the Angular viewer the Presentation options button has the same name as in the other viewers, and in every viewer both menu buttons announce that they open a menu.
- Visio viewers, OpenTeams viewers, `ooxml-ui/visio`, `ooxml-ui/teams`: F6 and Shift+F6 move between the parts of the window (ribbon, Shapes window, drawing, task pane, page tabs and status bar in Visio; app bar, chat list, header, messages and message box in Teams), as Word, Excel and PowerPoint already did. PowerPoint, Visio and Teams share one region service in `ooxml-ui`.
- `ooxml-core/xlsx`: a chart's alt text is kept when the drawing is saved again; it was dropped after the chart was moved.

## Accessibility

- `ooxml-ui/docx`, `ooxml-ui/xlsx`, `ooxml-ui/pptx`, `ooxml-ui/visio`: the arrow halves of ribbon split buttons meet the WCAG 2.2 target size of 24 by 24 pixels. Under PowerPoint's New Slide and Visio's Paste the extra space hangs below the button into the group label, so nothing moves.
- Office suite: the close button on a document tab is at least 24 pixels wide whatever font the system uses.
- `ooxml-core/chart`, Word viewers, Excel viewers, PowerPoint viewers, Visio viewers: a chart is named by its alt text, falling back to its title, and screen readers can read its series and values.
- `ooxml-ui`, Word viewers, Excel viewers, Visio viewers: the Tell me box, the Excel Name Box and formula bar, the search fields and the File tab show a visible focus ring with at least 3:1 contrast, in light and dark themes.
