## Breaking

- `ooxml-ui`: the theme no longer declares derived tokens (those whose default reads another token, such as `--office-accent-ink`, `--office-popover`, `--office-field-border` and `--office-select-background`) on `:root` or on the `data-office-theme` scopes. Each control resolves them where it reads them, so a container that overrides `--office-accent`, `--office-background` or `--office-control-border` now also changes the accent text, popovers and fields inside it. `themeBridge` and `shadcnBridge` no longer repeat those defaults on their selector. `isDerivedToken` names them.
- `ooxml-ui/docx`, `ooxml-ui/xlsx` and `ooxml-ui/visio`: the Word, Excel and Visio editors no longer inherit the page's CSS `color-scheme`. They take it from the new `--office-color-scheme` token, which is `light` unless the theme's dark mode applies (`data-office-theme="dark"`, or the system's dark preference where no `data-office-theme="light"` overrides it). A page that sets only `color-scheme: dark` on a container now gets light editors in it.
- `ooxml-ui`: the product `input` colours (`--dve-input`, `--xve-input`, `--pptx-input`) now default to `--office-control-border` instead of `--office-border`, and they colour the shared form controls inside the editor.

## Migration

- Code that read a derived token with `getComputedStyle(...).getPropertyValue('--office-…')` gets an empty string unless a host set it. Read it through `tok(name)` in CSS, or resolve its default from `OFFICE_TOKENS`.
- A page that themes a container dark with CSS `color-scheme: dark` alone sets `--office-color-scheme: dark` on it as well, or uses `data-office-theme="dark"`, which sets both, to keep dark Word, Excel and Visio editors.
- A host that wants lighter form boundaries sets `--office-control-border` (or the product's `input` colour); keep it at 3:1 against the background.

## Added

- `ooxml-core/color`: `contrastRatio`, `relativeLuminance`, `parseHexColor`, `readableTextColor`, `WCAG_TEXT_CONTRAST` and `WCAG_NON_TEXT_CONTRAST` for WCAG 2.x contrast checks. The PowerPoint accessibility checker now uses them.
- `ooxml-ui`: tokens `--office-accent-ink`, `--office-teams-brand-ink`, `--office-control-border`, `--office-canvas-gridline`, `--office-canvas-link` and `--office-color-scheme` (the theme's colour scheme as a value, `light` or `dark`).
- `ooxml-core/docx/ui` and `ooxml-core/xlsx/ui`: themes take an optional `primaryInk`, the primary colour as text (`--dve-primary-ink`, `--xve-primary-ink`). It defaults to `primary`, and the dark presets lift it.
- `ooxml-ui`: `shadcnBridge` and the product theme bridges map `<prefix>primary-ink` to `--office-accent-ink`, falling back to `<prefix>primary`.

## Changed

- `ooxml-ui`: form control boundaries (fields, selects, checkboxes, radios, switches) use the new `--office-control-border` token, `#8a8886` by default, so they reach 3:1 against the background. Decorative dividers keep `--office-border`. Hosts that set `--office-field-border`, `--office-checkbox-border` or `--office-switch-border` keep their values.
- `ooxml-ui`: accent text (selected ribbon tabs, selected options and backstage items, status bar links, Visio page tabs, Excel's selected headers and active sheet) uses the new `--office-accent-ink` token. It equals the accent in light mode and is lifted in dark mode so it reads at 4.5:1. Teams text in the brand colour uses `--office-teams-brand-ink` the same way.
- `ooxml-ui`: `--office-teams-brand-hover` now derives from `--office-teams-brand`, so a host that rebrands Teams gets a matching hover colour.
- Teams avatars (`office-ui-avatar`) pick black or white initials by computed contrast against their colour, and generated avatar colours are hex values.
- Office suite: hover colours of accent buttons follow the accent again instead of matching it, and form fields have visible 3:1 boundaries.

## Fixed

- `ooxml-ui`: a container-level `--office-accent` reaches accent text again (selected ribbon tabs, page and sheet tabs, Excel's selected headers). The accent ink is the accent in a light `color-scheme` and a lighter tint of it in a dark one, resolved where it is read.
- `ooxml-ui/visio`: `--vv-accent` colours the accent text again, ahead of the shared ink. The new `--vv-accent-text` sets that text alone and is documented with the other `--vv-*` overrides.
- `ooxml-ui/xlsx`: `--xve-selection-border` colours the selected header and the active sheet's name again, ahead of the shared ink. The Office suite no longer sets it to the raw accent, so those labels use the accent ink.
- `ooxml-ui/visio`: the current page tab reads at 4.5:1 in every accent; the page bar no longer tints the tab strip with the accent.
- Office suite: the Beta tag on the current app in the dark rail reads at 4.5:1, and the chat history search shows its focus ring.
- Form control boundaries reach 3:1: Word and Excel ribbon combo boxes and drop-downs, the ribbon's mode selector, the title bar search and Tell me boxes, PowerPoint's search, inspector fields and checkboxes (every binding), Excel's formula bar, name box and dialog fields, Visio's fields and shapes search, Teams search and the chat composer, and the suite's search, chat search and composer. The docx, xlsx and PowerPoint theme presets' `input` colours meet 3:1 too.

- `ooxml-ui/xlsx`: the sheet no longer changes with the interface theme. Gridlines use `--office-canvas-gridline` (Excel's `#e1e1e1`), which no theme remaps, and the freeze-pane line keeps its own grey. Before, dark mode drew dark gridlines on the white sheet.
- `ooxml-ui/xlsx`: the active sheet tab uses chrome colours, so it reads at 4.5:1 in dark mode instead of light accent text on white paper.
- PowerPoint viewers (React, Vue, Angular, Svelte, vanilla): the File page stays inside the viewer instead of covering the whole window, so a host's own navigation stays usable. Escape pressed inside it closes it and returns focus to the File tab; keys pressed elsewhere on the host page are left alone. `ooxml-ui/pptx` adds `activateBackstage`, and `activateModalFocus` takes a `keyScope` option.
- `ooxml-ui/docx`: hyperlinks on the page use the document link colour (`--office-canvas-link`, `#0563c1`) instead of the interface accent, which was hard to read in dark mode.

## Accessibility

- Forced-colours mode: the Visio current page tab keeps a visible label; PowerPoint's current slide thumbnail, pressed toggles (Landscape, inspector buttons) and selected tabs and options are marked with the system highlight in every binding; Word's active content control, Excel's applied filter buttons, slicer selections, dialog tabs, options and tiles, function suggestions, contextual ribbon tabs, tall icon ribbon buttons, building-block toggles and Visio's pressed buttons do the same. Forced-colours rules now outrank the accent rules they replace.

- `ooxml-ui`: in forced-colours mode (Windows contrast themes), a pressed ribbon button keeps its label. The browser's text backplate no longer paints over it.
- `ooxml-ui`, the product editors and the Office suite: selected, current, checked and pressed states (ribbon and pane tabs, sheet tabs, the suite's app rail, Teams lists, galleries, menus) keep a system highlight in forced-colours mode instead of disappearing. Excel's gridlines use the system's muted text colour there.
