## Changed

- `ooxml-ui`: form control boundaries (fields, selects, checkboxes, radios, switches) use the new `--office-control-border` token, `#8a8886` by default, so they reach 3:1 against the background. Decorative dividers keep `--office-border`. Hosts that set `--office-field-border`, `--office-checkbox-border` or `--office-switch-border` keep their values.
- `ooxml-ui`: accent text (selected ribbon tabs, selected options and backstage items, status bar links, Visio page tabs, Excel's selected headers and active sheet) uses the new `--office-accent-ink` token. It equals the accent in light mode and is lifted in dark mode so it reads at 4.5:1. Teams text in the brand colour uses `--office-teams-brand-ink` the same way.
- `ooxml-ui`: `--office-teams-brand-hover` now derives from `--office-teams-brand`, so a host that rebrands Teams gets a matching hover colour.
- Teams avatars (`office-ui-avatar`) pick black or white initials by computed contrast against their colour, and generated avatar colours are hex values.
- Office suite: hover colours of accent buttons follow the accent again instead of matching it, and form fields have visible 3:1 boundaries.

## Added

- `ooxml-core/color`: `contrastRatio`, `relativeLuminance`, `parseHexColor`, `readableTextColor`, `WCAG_TEXT_CONTRAST` and `WCAG_NON_TEXT_CONTRAST` for WCAG 2.x contrast checks. The PowerPoint accessibility checker now uses them.
- `ooxml-ui`: tokens `--office-accent-ink`, `--office-teams-brand-ink`, `--office-control-border`, `--office-canvas-gridline` and `--office-canvas-link`.
- `ooxml-core/docx/ui` and `ooxml-core/xlsx/ui`: themes take an optional `primaryInk`, the primary colour as text (`--dve-primary-ink`, `--xve-primary-ink`). It defaults to `primary`, and the dark presets lift it.
- `ooxml-ui`: `shadcnBridge` and the product theme bridges map `<prefix>primary-ink` to `--office-accent-ink`, falling back to `<prefix>primary`.

## Fixed

- `ooxml-ui/xlsx`: the sheet no longer changes with the interface theme. Gridlines use `--office-canvas-gridline` (Excel's `#e1e1e1`), which no theme remaps, and the freeze-pane line keeps its own grey. Before, dark mode drew dark gridlines on the white sheet.
- `ooxml-ui/xlsx`: the active sheet tab uses chrome colours, so it reads at 4.5:1 in dark mode instead of light accent text on white paper.
- PowerPoint viewers (React, Vue, Angular, Svelte, vanilla): the File page stays inside the viewer instead of covering the whole window, so a host's own navigation stays usable. Escape pressed inside it closes it and returns focus to the File tab; keys pressed elsewhere on the host page are left alone. `ooxml-ui/pptx` adds `activateBackstage`, and `activateModalFocus` takes a `keyScope` option.
- `ooxml-ui/docx`: hyperlinks on the page use the document link colour (`--office-canvas-link`, `#0563c1`) instead of the interface accent, which was hard to read in dark mode.

## Accessibility

- `ooxml-ui`: in forced-colours mode (Windows contrast themes), a pressed ribbon button keeps its label. The browser's text backplate no longer paints over it.
- `ooxml-ui`, the product editors and the Office suite: selected, current, checked and pressed states (ribbon and pane tabs, sheet tabs, the suite's app rail, Teams lists, galleries, menus) keep a system highlight in forced-colours mode instead of disappearing. Excel's gridlines use the system's muted text colour there.
