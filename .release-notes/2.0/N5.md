## Breaking

- `ooxml-core/opc`: `diffOpcPackages` rejects a package over the default limits (100 MiB of input, 100 MiB inflated, 10,000 parts). It used to read any package.
- `ooxml-core/pptx/signature-node`: OCSP revocation checks now use `node:http` and `node:https` instead of the global `fetch`. A replaced `globalThis.fetch`, a fetch dispatcher or a proxy configured for fetch no longer sees these requests. The connection goes to the address that was checked, so a responder name cannot change its answer afterwards.
- `ooxml-core/automation/node`, `ooxml-mcp` and the Word, Excel, PowerPoint and Visio MCP packages: on Windows, file tools refuse path segments that contain `:`, `<`, `>`, `"`, `|`, `?` or `*`, that end in a dot or a space, or that are device names such as `NUL` or `COM1`. They also refuse `/x`, which is rooted on the current drive, and `C:x`, which is relative to a drive's current folder. On every platform they refuse UNC and device paths, and paths starting with a backslash, before any filesystem call.
- `ooxml-core/chart`: `ChartWorkbookWrite` lists the cells to change: `cells` holds `{ index, value }` entries, where an empty value clears the cell, and `cellCount` is the size of the range. It replaces `values`. `chartSpaceWorkbookWrites` and `chartExSpaceWorkbookWrites` no longer write a chart's blank points, and given the chart as loaded they return only the cells the edit changed.
- `ooxml-core/chart`: `addChartCategory` no longer gives a category to a series that has none, and it puts the new category in the row after all the chart's data rather than after each series' own data.

## Migration

- `diffOpcPackages`: pass larger limits as the third argument, for example `diffOpcPackages(base, other, { maxInputBytes, maxEntryBytes, maxTotalBytes })`, or handle the rejection.
- OCSP: allow direct outbound HTTP and HTTPS from the Node process to public responders, intercept requests at the `node:http` level in tests, or pass `{ checkRevocation: false }` to `inspectPptxDigitalSignatures`. The status is then `not-checked` and no request is made.
- MCP file tools on Windows: rename files whose names Windows would reinterpret, and use a path relative to the root or a full absolute path inside it, with its drive and a separator after the colon.
- Code reading `ChartWorkbookWrite.values`: read `cells` instead. Code creating a write can build `cells` from a whole range with `chartWorkbookCells(values)` and set `cellCount` to the size of the range.
- `chartSpaceWorkbookWrites(space)` and `chartExSpaceWorkbookWrites(space, resolve)` still return every cached point. Pass the chart as loaded (`chartSpaceWorkbookWrites(space, before)`, `chartExSpaceWorkbookWrites(space, resolve, before)`) to get only the edit, including the cells it emptied.

## Added

- `ooxml-core/pptx/signature-node`: `inspectPptxDigitalSignatures(data, { checkRevocation: false })` makes no network request and reports the revocation status as `not-checked`.
- `ooxml-core/chart`: `MAX_HISTOGRAM_BINS` and `histogramBinsLimited`, and `chartExSummary` sets `histogramBinsLimited` when a histogram asks for more bins than are drawn.
- `ooxml-core/chart`: `chartPointBudget`, `MAX_CHART_BLANK_POINTS` and the `CHART_POINTS_LIMITED` parse issue. `parseChartSpace`, `parseChartExSpace` and `chartExSummary` accept a `pointBudget` so that all the charts of a package share one, and `chartExSummary` sets `pointsLimited` when a view is shorter than the declared points.
- `ooxml-core/chart`: `setChartSeriesPoint` sets one value in any row of a series, `chartRowCount` gives the rows of a chart's data, and `chartPartWorkbookWrites` gives the workbook writes between two saved chart parts.
- `ooxml-core/opc`: `ZipLimits.createOpenError` chooses the error for input that is not a readable zip, and `diffOpcPackages` accepts limits.

## Changed

- `ooxml-core`: charts keep the point counts and points their file declares, however large, through viewing, editing and saving. Blank positions in the views hosts draw and edit come from a budget of 4,194,304 per package, at most 1,048,576 per view and shared among the views of a part. A view past the budget shows fewer trailing blanks, then only its first points, and the load reports it (`CHART_POINTS_LIMITED`, a PowerPoint or Excel load warning). Such a chart stays fully editable in Excel, Word, PowerPoint and Visio: values, categories and series can all change. A category added or removed works inside the declared range, so its count stays and the points past the view stay, moving up with a removed row.
- `ooxml-core/automation/node` and the MCP packages: an absolute path may reach the root through a link, a Windows short name or the real path of a linked root. On POSIX systems, names such as `a: b.docx`, `aux/`, `why?.docx` and `a\b.docx` are ordinary files: a backslash inside a name is not a separator there.

## Fixed

- `ooxml-core`: histogram binning runs in linear time for charts with underflow or overflow bins.
- PowerPoint charts: saving no longer turns blank points into zeros or empty points, and data that did not change keeps its caches as written, on every save path.
- PowerPoint, Word and Visio charts: saving an edit writes only the workbook cells that edit changed. Cells the chart caches differently from what they hold keep their content; before, a text cell in a value range, which a chart caches as 0, was overwritten with 0 by any chart save, even a rename. Blank points no longer create cells, and in PowerPoint marking a point blank now reaches the workbook.
- PowerPoint charts: adding or removing a series on a chart with a very long range and an embedded workbook no longer fails with a stack overflow, and the new data sheet stores only the cells that hold data.
- Word and Visio charts: Edit Data no longer refuses a value edit on a series shorter than the longest one in a chart with a whole-column range.
- Chart style presets add per-point formatting only for points that exist.
- Office suite: the OneDrive conflict details still list why the edits were not combined when the packages cannot be compared.

## Security

- `ooxml-core`: every package is now opened through the guarded zip reader, including signature listing, package comparison, Visio collaboration snapshots and embedded chart workbooks, so a small file can no longer inflate without limit. Signature listing also ignores a package whose signature part is larger than 16 MiB. A repository check keeps every shipped folder on this path.
- `ooxml-core`: a ChartEx histogram draws at most 1,000 bins, whatever bin count or bin size the file asks for. Before, a chart of a few hundred bytes could exhaust memory.
- `ooxml-core`: chart point counts and point indices no longer decide how much memory is allocated, in classic charts, ChartEx parts, data sheets, edits, PowerPoint's hidden series and label ranges, and embedded chart workbooks, whether a package holds one chart part or thousands. Before, a chart of a few hundred bytes could exhaust memory.
- `ooxml-core`: the fast XML reader no longer treats names such as `constructor` as known entities or namespace prefixes.
- `ooxml-core`, `ooxml-mcp` and the MCP packages: dangerous paths are refused on their text before any filesystem call, so a UNC path no longer reaches a remote host, refused paths all return one error, and an alternate data stream name can no longer create a file past the extension check.
- `ooxml-core/pptx/signature-node`: OCSP requests go only to globally routable addresses, and the connection is made to the address that was checked.
