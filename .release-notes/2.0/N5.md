## Breaking

- `ooxml-core/opc`: `diffOpcPackages` rejects a package over the default limits (100 MiB of input, 100 MiB inflated, 10,000 parts). It used to read any package.
- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: OCSP revocation checks now use `node:http` and `node:https` instead of the global `fetch`. A replaced `globalThis.fetch`, a fetch dispatcher or a proxy configured for fetch no longer sees these requests. The connection goes to the address that was checked, so a responder name cannot change its answer afterwards.
- `ooxml-core/automation/node` and MCP packages: on Windows, file tools refuse path segments that contain `:`, `<`, `>`, `"`, `|`, `?` or `*`, that end in a dot or a space, or that are device names such as `NUL` or `COM1`. They also refuse `/x`, which is rooted on the current drive, and `C:x`, which is relative to a drive's current folder. On every platform they refuse UNC and device paths, and paths starting with a backslash, before any filesystem call.
- `ooxml-core/chart`: `ChartWorkbookWrite` lists the cells to change. `cells` holds `{ index, value }` entries, where an empty value clears the cell, and `cellCount` is the size of the range. It replaces `values`. `chartSpaceWorkbookWrites` and `chartExSpaceWorkbookWrites` no longer write a chart's blank points, and given the chart as loaded they return only the cells the edit changed.
- `ooxml-core/chart`: `addChartCategory` no longer gives a category to a series that has none, and it puts the new category in the row after all the chart's data rather than after each series' own data.

## Migration

- `ooxml-core/opc`: for `diffOpcPackages`, pass larger limits as the third argument, for example `diffOpcPackages(base, other, { maxInputBytes, maxEntryBytes, maxTotalBytes })`, or handle the rejection.
- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: for OCSP, allow direct outbound HTTP and HTTPS from the Node process to public responders, intercept requests at the `node:http` level in tests, or pass `{ checkRevocation: false }` to `inspectPptxDigitalSignatures`. The status is then `not-checked` and no request is made.
- `ooxml-core/automation/node` and MCP packages: on Windows, rename files whose names Windows would reinterpret. Use a path relative to the root, or a full absolute path inside it with its drive and a separator after the colon.
- `ooxml-core/chart`: code reading `ChartWorkbookWrite.values` reads `cells` instead. Code creating a write can build `cells` from a whole range with `chartWorkbookCells(values)` and set `cellCount` to the size of the range.
- `ooxml-core/chart`: `chartSpaceWorkbookWrites(space)` and `chartExSpaceWorkbookWrites(space, resolve)` still return every cached point. Pass the chart as loaded (`chartSpaceWorkbookWrites(space, before)`, `chartExSpaceWorkbookWrites(space, resolve, before)`) to get only the edit, including the cells it emptied.

## Added

- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: `inspectPptxDigitalSignatures(data, { checkRevocation: false })` makes no network request and reports the revocation status as `not-checked`.
- `ooxml-core/chart`: `MAX_HISTOGRAM_BINS` and `histogramBinsLimited`. `chartExSummary` sets `histogramBinsLimited` when a histogram asks for more bins than are drawn.
- `ooxml-core/chart`: `chartPointBudget`, `MAX_CHART_BLANK_POINTS` and the `CHART_POINTS_LIMITED` parse issue. `parseChartSpace`, `parseChartExSpace` and `chartExSummary` accept a `pointBudget` so that all the charts of a package share one, and `chartExSummary` sets `pointsLimited` when a view is shorter than the declared points.
- `ooxml-core/chart`: `chartSpaceRangeConflicts` lists the references of a chart whose ranges cannot hold what they cache. `ChartWorkbookWrite.only` marks a write whose range holds nothing but its cells, and `chartSpaceWorkbookWrites` sets it for a range the chart as loaded did not read.
- `ooxml-core/chart`: `setChartSeriesPoint` sets one value in any row of a series, `chartRowCount` gives the rows of a chart's data, and `chartPartWorkbookWrites` gives the workbook writes between two saved chart parts.
- `ooxml-core/opc`: `ZipLimits.createOpenError` chooses the error for input that is not a readable zip, and `diffOpcPackages` accepts limits.
- `ooxml-core/pptx` and `pptx-viewer-core`: `PptxChartData.structureEdits` lists the rows and series added or removed since the chart was loaded or saved. `chartDataAddCategory`, `chartDataRemoveCategory`, `chartDataAddSeries`, `chartDataRemoveSeries`, the chart grid operations and `chartDataApplySheetEdits` record them, and saving replays them through the same chart operations Word, Excel and Visio use.
- `ooxml-core/chart`: `appendChartWorkbookSheet` takes `reuse`, a sheet to write the rows over instead of adding one, and `drop`, sheets to remove with their parts, their sheet-scoped names and their place in the tab order. `appendChartExWorkbookData` takes the same two options and returns the name of the sheet it wrote.
- `ooxml-core/chart`: `writeChartWorkbookUpdates` returns the cells it changed (`changes`), `restoreChartWorkbookCells` puts them back where they still hold what was written, and `ChartWorkbookPackage.write` receives them.

## Changed

- `ooxml-core`, `pptx-viewer-core`, PowerPoint viewers, Word viewers, Excel viewers and Visio viewers: charts keep the point counts and points their file declares, however large, through viewing, editing and saving. Blank positions in the views hosts draw and edit come from a budget of 4,194,304 per package, at most 1,048,576 per view and shared among the views of a part. A view past the budget shows fewer trailing blanks, then only its first points, and the load reports it (`CHART_POINTS_LIMITED`, a PowerPoint or Excel load warning). Such a chart stays fully editable in Excel, Word, PowerPoint and Visio, so values, categories and series can all change. A category added or removed works inside the declared range, so its count stays and the points past the view stay. A removed row moves the later points of every series up, even a series whose view ends before that row, as deleting the worksheet row does in Excel.
- `ooxml-core/pptx`, `pptx-viewer-core` and PowerPoint viewers: `chartDataAddCategory` and the grid's Add Category put the new row after all of a chart's data, padding a shorter series with blank points, and name it after the rows the chart has. A chart whose rows have no category labels gets none. `chartDataAddSeries` and Add Series give the new series a value for every row of a chart with categories.
- `ooxml-core/chart`: `removeChartSeries` moves the plot order of every later series up one, as Excel does. The series' `c:idx` stays.
- `ooxml-core/automation/node` and MCP packages: an absolute path may reach the root through a link, a Windows short name or the real path of a linked root. On POSIX systems, names such as `a: b.docx`, `aux/`, `why?.docx` and `a\b.docx` are ordinary files, and a backslash inside a name is not a separator there.

## Fixed

- `ooxml-core/chart` and Excel viewers: histogram binning runs in linear time for charts with underflow or overflow bins.
- `ooxml-core/pptx`, `pptx-viewer-core` and PowerPoint viewers: saving a chart no longer turns blank points into zeros or empty points, and data that did not change keeps its caches as written, on every save path.
- `ooxml-core`, `pptx-viewer-core`, PowerPoint viewers, Word viewers and Visio viewers: saving a chart edit writes only the workbook cells that edit changed. Cells the edit does not change keep their content, even when the chart caches them differently from what they hold. Before, a text cell in a value range, which a chart caches as 0, was overwritten with 0 by any chart save, even a rename. Adding or removing a category or series through Edit Data updates the workbook cell by cell in PowerPoint, as in Word and Visio, and PowerPoint no longer writes such an edit to a new sheet. Removing a category writes the cells below the removed row from the chart's cache, so a text cell in a value range does not move up with its row as it does when Excel deletes the row. Blank points no longer create cells, and in PowerPoint marking a point blank now reaches the workbook.
- `ooxml-core/pptx`, `pptx-viewer-core` and PowerPoint viewers: removing a chart category saves the row that was removed. PowerPoint used to work out the removed row by comparing the data before and after. A blank row inside one series' view reads the same as a row past the end of another's, so on a chart over whole columns it could remove a different row and move a series' far points up twice. The chart now matches what deleting the worksheet row in Excel gives, as in Word and Visio.
- `ooxml-core/pptx`, `pptx-viewer-core` and PowerPoint viewers: undoing a chart category or series edit after a save, then saving, gives back the chart part the data was edited from, with its ranges, caches and workbook cells in agreement. Before, the cache came back while the range kept the removed row's size.
- `ooxml-core/pptx`, `pptx-viewer-core` and PowerPoint viewers: every chart save writes ranges that hold the data the chart caches, so the chart part and its embedded workbook agree whichever way the save was made. When a part's ranges cannot hold its data, the data moves to a data sheet of its own in the workbook. Before, data that undo or redo brought back to a state no longer kept could save with both series reading the same cells, ranges of another length than the cached points, and zeros cached for a series the workbook did not hold. A chart PowerPoint saved over hidden rows, which caches only the visible ones, keeps its ranges.
- `ooxml-core`, `pptx-viewer-core`, PowerPoint viewers, Word viewers and Visio viewers: a save that makes a chart read a range it did not read before, such as undoing the removal of a series, empties the numbers left in that range where the chart shows a blank point. Text in a value range stays.
- `ooxml-core`, `pptx-viewer-core`, PowerPoint viewers, Word viewers and Visio viewers: removing a row of a bubble chart removes its bubble sizes with it. Before, each bubble took the size of the row below. Adding a row to a scatter or bubble chart leaves the new x value blank instead of writing a category label into the x values, which turned them into text.
- `ooxml-core/pptx`, `pptx-viewer-core` and PowerPoint viewers: a chart that names no category labels, which Excel labels 1, 2, 3, no longer takes labels from the first column of its embedded workbook, which can hold a series of its own or the x values of a scatter chart. Undoing to a state saved earlier then gives back that part exactly, and a reload shows the categories the chart had.
- `ooxml-core/pptx`, `pptx-viewer-core` and PowerPoint viewers: undoing and redoing a chart category or series edit, then saving each time, no longer grows the presentation. Each save that moved a chart's data used to add a sheet with a full copy of the data to its embedded workbook. A chart of 2,000 rows went from 86 KB to 764 KB in 20 round trips, the last taking 12 seconds. It now stays at 105 KB and 2 seconds. A save now writes over the data sheet it added earlier for the same chart, and removes the ones it added that no chart and no undo state reads, so the same state always saves the same workbook. Sheets the workbook had when it was opened are never written over or removed. The same holds for ChartEx charts such as box and whisker or funnel, which added a sheet on every series edit.
- `ooxml-core/pptx`, `pptx-viewer-core` and PowerPoint viewers: when two charts share one embedded workbook and a save writes only part of one chart's data, the next save puts back only the cells that chart wrote, so the other chart's write stays.
- `ooxml-core/pptx`, `pptx-viewer-core` and PowerPoint viewers: adding or removing a chart series on a chart with a very long range and an embedded workbook no longer fails with a stack overflow, and the new data sheet stores only the cells that hold data.
- `ooxml-core/pptx`, `pptx-viewer-core` and PowerPoint viewers: a chart on a duplicated slide writes its data into its own copy of the embedded workbook. Before, edits to the copy were written into the original chart's workbook.
- `ooxml-core/pptx`, `pptx-viewer-core` and PowerPoint viewers: a chart series added after removing a series is given as many rows in one save as it is when a save comes between the two edits. On a chart over whole columns, removing the longest series used to leave the rows only it reached for the next series added.
- `ooxml-core/pptx` and `pptx-viewer-core`: the SDK's `removeChartCategory` and `addChartCategory` keep each series' blank points on their rows, move per-point formatting with its point, and work on a chart whose rows have no category labels. They make the same edit as `chartDataRemoveCategory` and `chartDataAddCategory`, in place like the SDK's other chart edits. The element keeps its `chartData` object and its series objects, so code holding them sees the edit.
- `ooxml-core`, Word viewers and Visio viewers: Edit Data no longer refuses a value edit on a series shorter than the longest one in a chart with a whole-column range.
- `ooxml-core/chart`: chart style presets add per-point formatting only for points that exist.
- Office suite: the OneDrive conflict details still list why the edits were not combined when the packages cannot be compared.

## Performance

- `ooxml-core/pptx`, `pptx-viewer-core` and PowerPoint viewers: saving a chart no longer keeps the chart's part and data for each of the last 100 saves, which made the heap grow with every save, by gigabytes for a chart of a few hundred thousand points. A saved state is kept only while undo or redo can still return to it, compressed and without a second copy of its data, and the states a presentation keeps stay under 32 MiB, oldest released first. History copied with `cloneSlide` keeps its saved state alive. A copy made with `structuredClone` or JSON finds its state while other chart data still holds it. Data that undo brings back to a state that is gone or released is saved as data edited from the chart as it is now: the chart part shows it in full and the embedded workbook holds what the chart shows, on a data sheet of its own when rows or series changed.

## Security

- `ooxml-core`, `pptx-viewer-core`, `docx-core`, `@christophervr/xlsx-core`, `visio-core`, PowerPoint viewers, Word viewers, Excel viewers and Visio viewers: every package is now opened through the guarded zip reader, including signature listing, package comparison, Visio collaboration snapshots and embedded chart workbooks, so a small file can no longer inflate without limit. Signature listing also ignores a package whose signature part is larger than 16 MiB. A repository check keeps every shipped folder on this path.
- `ooxml-core/chart` and Excel viewers: a ChartEx histogram draws at most 1,000 bins, whatever bin count or bin size the file asks for. Before, a chart of a few hundred bytes could exhaust memory.
- `ooxml-core`, `pptx-viewer-core`, PowerPoint viewers, Word viewers, Excel viewers and Visio viewers: chart point counts and point indices no longer decide how much memory is allocated. This covers classic charts, ChartEx parts, data sheets, edits, PowerPoint's hidden series and label ranges, and embedded chart workbooks, whether a package holds one chart part or thousands. Before, a chart of a few hundred bytes could exhaust memory.
- `ooxml-core` and `pptx-viewer-core`: the fast XML reader no longer treats names such as `constructor` as known entities or namespace prefixes.
- `ooxml-core/automation/node` and MCP packages: dangerous paths are refused on their text before any filesystem call, so a UNC path no longer reaches a remote host, refused paths all return one error, and an alternate data stream name can no longer create a file past the extension check.
- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: OCSP requests go only to globally routable addresses, and the connection is made to the address that was checked.
