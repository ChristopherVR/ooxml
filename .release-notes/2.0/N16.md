## Breaking

- PowerPoint viewers (`pptx-react-viewer`, `pptx-vue-viewer`, `pptx-angular-viewer`, `pptx-svelte-viewer`, `pptx-vanilla-viewer`, and `ooxml-ui/pptx`) no longer download a presentation's linked pictures, fills, backgrounds, bullets, audio, video, online videos or the sounds of its animations, slide transitions and hyperlinks when it opens. As in Microsoft PowerPoint, a security bar under the ribbon says "References to external pictures and other media have been blocked" and offers **Enable Content**, which then shows them. Nothing reloads: edits, the unsaved state, the slide on screen, undo history and AutoRecover carry on. The bar shows with or without the toolbar. The choice lasts until another presentation is opened and is not stored.
- In a collaboration session each participant decides for themselves: the linked addresses are part of the shared deck, and a participant's browser requests them only after that participant chooses Enable Content.
- The File > Options > Trust Center option "Allow external content" is now off by default.
- Viewers keep linked addresses in the presentation model (they load with `allowExternalImages: true`) and decide what to draw per viewer. A host that draws slides itself from the viewer's model, rather than through the binding's components, must read them through `linkedContentView(value, allowed)` from `ooxml-ui/pptx`, or it will request the linked content.
- `ooxml-ui/pptx`: `applySlideTransitionSound(transition, sources)` now takes the viewer's media map and linked-content consent (`DeckSoundSources`) and plays through `playDeckSound`; the `(transition, resolveUrl, player)` form and `TransitionSoundPlayer` are removed. `withholdLinkedContent`, `linkedContentView` and `hasLinkedContent` now treat every model field that names a resource (a name ending in `Path`, `Data`, `Url`, `Image` or `Src`) as fetched, so they also withhold linked sounds and any linked content added later; hyperlink addresses and text are kept.

## Migration

- To keep downloading linked content without asking, pass `allowExternalContent: true` (the equivalent of PowerPoint's "Unblock automatic download of linked images" policy). To block it without showing the bar, pass `allowExternalContent: false`.
- Readers who want automatic downloads can turn on File > Options > Trust Center > "Allow external content".
- A custom shell built from building blocks renders the security bar from `externalContent` and passes `externalContent.allowed` to slides it draws itself (`linkedContent` on `SlideThumbnail`, `renderSlideStage`, `renderSlideThumbnail` and `createSlidesPane`).

## Added

- `ooxml-ui`: `<office-ui-message-bar>`, the Office message bar, and `<pptx-ui-external-content-bar>`, PowerPoint's security bar for linked content, translated into every viewer language.
- `ooxml-ui`: `playDeckSound`, `stopDeckSound`, `resolveDeckSound` and `BUILT_IN_SOUNDS`, the one way a viewer plays a sound from a deck: a linked sound plays only once that viewer allows linked content.
- `ooxml-ui`: `resolveExternalContentView` (what a viewer draws and whether the bar shows), `linkedContentView`, `linkedContentUrl`, `withholdLinkedContent` and `hasLinkedContent`, which every binding uses to draw the deck without its linked addresses until the viewer allows them; `dispatchExternalContentBarIntent` routes the bar's buttons; `renderSlideStage` takes `linkedContent`.
- Building blocks in every binding expose the security bar the same way: `externalContent` (`{ barVisible, allowed, enable, close }`, the `ViewerExternalContentBar` type from `ooxml-ui/pptx`) and the binding's `ExternalContentBar` component (`ExternalContentBarComponent` in `pptx-angular-viewer`, `mountExternalContentBar` and `createExternalContentBar` in `pptx-vanilla-viewer`). The building-blocks canvas does not draw the bar; the host shell renders it.

## Fixed

- PowerPoint viewers play a linked slide-transition sound once the reader chooses Enable Content; before, its address was joined onto the slide's folder and it could never play. `ooxml-core` keeps a linked transition or hyperlink sound's address only when the load allows linked content (`allowExternalImages`), like every other linked relationship.
- `pptx-vanilla-viewer`: the Slide Master pane's button that leaves master view is named "Close master view", as in the other bindings, instead of "Collapse master pane", so it is no longer mistaken for the security bar's Close.

## Security

- Opening a presentation no longer tells the servers it links to that it was opened, or the reader's IP address, until the reader chooses Enable Content, and a collaborator's choice never makes another reader's browser contact them. This covers the slide show too: a linked animation, transition or hyperlink sound is not requested before Enable Content, including with `allowExternalContent: false`.
