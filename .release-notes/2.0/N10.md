## Added

- `visio-viewer` has a `locale` property, and `locale` is part of the Visio viewer contract, so React, Vue, Solid, Svelte, Angular and vanilla hosts can set the interface language as a prop (`ooxml-core`, `ooxml-ui`, the `visio-*` viewer packages).

## Changed

- Changing `surfaceOnly` on an `xlsx-editor` that has already been attached to the page now throws, as it does on `docx-editor`. Choose it before the editor first connects (`ooxml-ui`, `xlsx-*` viewer packages).
- A `docx-editor` or `xlsx-editor` sharing a room leaves the room when it is removed from the page and not attached again before the current task ends, and joins the same room again when it is attached later. Moving an editor between parents in one task keeps it in the room (`ooxml-ui`, `docx-*` and `xlsx-*` viewer packages).

## Fixed

- `docx-editor` and `xlsx-editor` no longer stay in memory after they are removed from the page. Print, font and ribbon listeners are released on removal and restored when the same element is attached again, so printing, font updates and ribbon tabs keep working after a move. Menus, popups, Excel's AutoFilter menu and form control lists still open at that moment are closed. A Word editor that was typed in is freed too, and so is an editor removed while it shares a room it opened (`ooxml-ui`, `docx-*` and `xlsx-*` viewer packages, and the Office suite).
- Removing one Word or Excel editor no longer closes a ribbon popover, overflow menu or word count panel open in another editor on the same page (`ooxml-ui`).
- A property set on an element before its definition loaded now counts as written just after the element upgrades, for every `ooxml-ui` element: it wins over the attributes the element had then, any later property or attribute write wins over it, and it applies before the element first connects. An early `surfaceOnly` on `docx-editor` or `xlsx-editor` now mounts only the editing surface (Word used to build the whole application and then throw; Excel ignored it), and an early `readOnly` or `locale` is no longer replaced by a `read-only` or `locale` attribute. Properties that Lit declares on the shared elements keep Lit's rule (`ooxml-ui`).
- The Word, Excel and Teams Solid components render during server rendering instead of throwing `document is not defined`, and the browser reuses the server's element when it hydrates (`ooxml-ui`, `docx-solid-viewer`, `xlsx-solid-viewer`, `openteams-solid-viewer`).
- Every element definition now carries the version stamp, so `docx-editor`, `xlsx-editor`, `visio-viewer`, `pptx-three-view` and the `teams-*` elements also refuse to load next to an incompatible `ooxml-ui` build (`ooxml-ui`).

## Performance

- Opening and closing a Word or Excel document in a long session no longer grows memory by the size of the editor each time: in the Office suite, Word went from about 3 MB and 12,000 DOM nodes per cycle to about 0.2 MB and none, and Excel from about 13 MB and 4,000 nodes to about 0.2 MB and none, with no growth in event listeners.
