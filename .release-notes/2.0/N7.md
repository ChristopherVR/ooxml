## Breaking

- `ooxml-ui/pptx/ai` and PowerPoint viewers: theme and presentation-level assistant tools now follow `writePolicy`. Under `stage` and `approve` they create proposals instead of applying at once.
- `ooxml-ui/pptx/ai` and PowerPoint viewers: `writePolicy: 'approve'` now means each change must be accepted on its own, and `acceptAll()` skips those changes. `delete_slides` and `import_from_json` behave this way under every policy.
- `ooxml-ui/pptx/ai`: `StagedProposal` no longer has an `updater`, and `buildToolExecutors` takes a run limiter as its fourth argument instead of an animator.
- `ooxml-ui/pptx/ai`: `session.transport` already adds the deck and focus context, so a binding or host must not add its own.
- `ooxml-ui/pptx/ai`: `PptxAiBridge` and `PptxAiBridgePort` require `getDeckLoad()`, which names the presentation load the deck comes from. Staged proposals belong to one load.

## Migration

- `ooxml-ui/pptx/ai` and PowerPoint viewers: hosts that relied on theme or metadata tools applying immediately should set `writePolicy: 'auto'`, or accept the proposals.
- `ooxml-ui/pptx/ai`: read `requiresApproval` and `conflict` on `ProposalView` when you render your own review list. `proposals.apply(id)` returns `false` for a conflict and keeps the proposal listed.
- `ooxml-ui/pptx/ai`: show "accept all" with `canAcceptAllProposals(proposals)`.
- `ooxml-ui/pptx/ai`: a custom bridge or port implements `getDeckLoad()`. Return a new number each time the host loads a presentation (open, reopen, File > New, recovery restore, or a collaboration join whose room replaces the slides) and the same number through every edit, including ones that replace the handler.
- `ooxml-ui/pptx/ai`: a custom proposal list shows why it emptied when `proposals.discarded` is true, for example with the `pptx.ai.proposalsDiscarded` string.

## Added

- `ooxml-ui/pptx/ai` and PowerPoint viewers: `limits` on the assistant config stops a run at a number of steps, tool calls, repeated calls or a time limit, with defaults of 16, 48, 4 and 10 minutes.
- `ooxml-ui/pptx/ai`: `getLastFinish()` reports how the latest request ended, in one set of reasons for every provider.
- `ooxml-ui/pptx/ai`: `checkPptxAiBridgeReadsItsWrites(bridge)` reports whether a custom `PptxAiBridge` returns its own writes from the next read, which Apply all relies on.
- `ooxml-ui/pptx/ai`: `ProposalStore.discarded` reports that a presentation load dropped the staged proposals, until another is staged.
- `ooxml-ui/pptx`: `createRoomJoinTracker()` tells a binding when a collaboration room's slides replace the open deck, and `observeExternalCollaborationReadiness` reports the same through `onRoomReplacedDeck`.
- `ooxml-ui/pptx`: `withThemeUpdates(state, updates)` re-resolves the slides and the master and layout elements for a new colour scheme, font scheme or theme name, without touching the handler.

## Changed

- `ooxml-ui/pptx/ai`: applying a theme proposal passes `applyTheme` only the theme parts that proposal changed.
- `ooxml-ui/pptx/ai`: a `ProposalStore` belongs to the presentation load it was made on. When the bridge's `getDeckLoad()` changes, the staged proposals are dropped and can no longer be listed or applied. A new handler alone no longer drops them.
- `ooxml-ui/pptx/ai`: every `ProposalStore` built on one bridge shares the staged proposals, so a panel that is closed and opened again, or rebuilt by a load, keeps them or says that the load dropped them.

## Fixed

- PowerPoint viewers: accepting several assistant proposals no longer keeps only the last one, and accepting a proposal no longer erases edits made after it was staged. Overlapping changes are reported as a conflict.
- `pptx-react-viewer` and `@christophervr/pptx-viewer`: Apply all no longer loses theme, document property and text changes. Each change now sees the one before it without waiting for a render, and each applied slide change is its own undo step.
- `pptx-react-viewer` and `@christophervr/pptx-viewer`: after another presentation is opened, the assistant no longer reads the previous deck's document properties, so a later change or save can no longer write them into the new deck.
- `pptx-svelte-viewer`: an assistant theme change now re-colours the slides, is saved with the file and is one undo step, as in the other viewers. Before, it changed only the theme the panel reported.
- PowerPoint viewers: opening another presentation now discards the assistant's pending suggestions in every framework, and the panel says so. The vanilla and Svelte viewers kept listing them.
- PowerPoint viewers: staged assistant suggestions survive Insert Layout, the other Slide Master view commands and slide paste, and still apply. The React, vanilla and Svelte viewers dropped them without a word, and the Vue and Angular viewers kept cards whose Apply did nothing.
- PowerPoint viewers: joining a collaboration session whose room replaces the slides discards the suggestions staged on the previous deck and says so, instead of offering cards that no longer fit the deck.
- `pptx-react-viewer` and `@christophervr/pptx-viewer`: assistant writes not yet rendered survive Slide Master view commands and slide paste.
- `pptx-vue-viewer` and `pptx-svelte-viewer`: with a `model` connection each tool runs once. Tools ran twice before, so every proposal was listed twice. In Svelte the canvas still follows the assistant's tool calls.
- `pptx-vanilla-viewer`: assistant font and theme name changes now reach the deck, are visible to the assistant and can be undone with the theme colours.
- `pptx-vanilla-viewer`: sending a message while the assistant was still loading reloaded the page and lost the open deck. The message box now appears when the assistant is ready, as in the other viewers.
- `pptx-angular-viewer`: assistant colour changes apply to a deck whose theme has no font scheme.
- PowerPoint viewers: `import_from_json` and theme tools can no longer change the deck before the user accepts them.
- PowerPoint viewers: every framework now sends the deck outline and the user's focus to the model. Only React did before.
- PowerPoint viewers: assistant tool calls are validated against their schemas before they run, so malformed values can no longer reach the deck.
- PowerPoint viewers: the assistant reports a reply that was cut off, filtered or ended without a finish signal. The vanilla viewer now shows the error text.
- `ooxml-core/pptx`, `pptx-viewer-core` and PowerPoint viewers: Insert Slide Master, Duplicate Master and Insert Layout now give every slide master and layout an id no other master or layout uses. They reused ids before, so pasting slides into the presentation afterwards failed.
- `ooxml-core/automation`, `pptx-viewer-mcp` and `ooxml-mcp`: `update_metadata`, `update_theme_colors`, `update_theme_fonts` and `apply_theme_preset` now save their changes to the file.
- `ooxml-core/automation`: `createLiveToolHost` can edit PowerPoint decks. A real change made while an edit is prepared is still refused.
- Office suite: a reply cut off by the length limit, stopped by a filter or ended without a finish signal keeps its text, says so and offers no actions.
