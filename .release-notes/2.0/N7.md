## Breaking

- `ooxml-ui/pptx/ai`: theme and presentation-level assistant tools now follow `writePolicy`. Under `stage` and `approve` they create proposals instead of applying at once.
- `ooxml-ui/pptx/ai`: `writePolicy: 'approve'` now means each change must be accepted on its own, and `acceptAll()` skips those changes. `delete_slides` and `import_from_json` behave this way under every policy.
- `ooxml-ui/pptx/ai`: `StagedProposal` no longer has an `updater`, and `buildToolExecutors` takes a run limiter as its fourth argument instead of an animator.
- `ooxml-ui/pptx/ai`: `session.transport` already adds the deck and focus context, so a binding or host must not add its own.

## Migration

- Hosts that relied on theme or metadata tools applying immediately should set `writePolicy: 'auto'`, or accept the proposals.
- Read `requiresApproval` and `conflict` on `ProposalView` when you render your own review list. `proposals.apply(id)` returns `false` for a conflict and keeps the proposal listed.
- Show "accept all" with `canAcceptAllProposals(proposals)`.

## Added

- `ooxml-ui/pptx/ai` and all PowerPoint viewer packages: `limits` on the assistant config stops a run at a number of steps, tool calls, repeated calls or a time limit, with defaults of 16, 48, 4 and 10 minutes.
- `ooxml-ui/pptx/ai`: `getLastFinish()` reports how the latest request ended, in one set of reasons for every provider.
- `ooxml-ui/pptx/ai`: `checkPptxAiBridgeReadsItsWrites(bridge)` reports whether a custom `PptxAiBridge` returns its own writes from the next read, which Apply all relies on.

## Changed

- `ooxml-ui/pptx/ai`: applying a theme proposal passes `applyTheme` only the theme parts that proposal changed.

## Fixed

- PowerPoint viewer packages: accepting several assistant proposals no longer keeps only the last one, and accepting a proposal no longer erases edits made after it was staged. Overlapping changes are reported as a conflict.
- `pptx-react-viewer`: Apply all no longer loses theme, document property and text changes. Each change now sees the one before it without waiting for a render, and each applied slide change is its own undo step.
- `pptx-vue-viewer` and `pptx-svelte-viewer`: with a `model` connection each tool runs once. Tools ran twice before, so every proposal was listed twice. In Svelte the canvas still follows the assistant's tool calls.
- `pptx-vanilla-viewer`: assistant font and theme name changes now reach the deck, are visible to the assistant and can be undone with the theme colours.
- `pptx-vanilla-viewer`: sending a message while the assistant was still loading reloaded the page and lost the open deck. The message box now appears when the assistant is ready, as in the other viewers.
- `pptx-angular-viewer`: assistant colour changes apply to a deck whose theme has no font scheme.
- PowerPoint viewer packages: `import_from_json` and theme tools can no longer change the deck before the user accepts them.
- PowerPoint viewer packages: every framework now sends the deck outline and the user's focus to the model. Only React did before.
- PowerPoint viewer packages: assistant tool calls are validated against their schemas before they run, so malformed values can no longer reach the deck.
- PowerPoint viewer packages: the assistant reports a reply that was cut off, filtered or ended without a finish signal. Vanilla now shows the error text.
- `ooxml-core`: `update_metadata`, `update_theme_colors`, `update_theme_fonts` and `apply_theme_preset` now save their changes to the file.
- `ooxml-core`: `createLiveToolHost` can edit PowerPoint decks. A real change made while an edit is prepared is still refused.
- Office suite: a reply cut off by the length limit, stopped by a filter or ended without a finish signal keeps its text, says so and offers no actions.
