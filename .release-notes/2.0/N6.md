## Breaking

- `ooxml-core/pptx` and every PowerPoint viewer: slides read from a collaboration room (`readSlidesFromYDoc`, `readSlideFromYMap`) are now checked. An element id that is not in safe token form is encoded the way the loader encodes part names. A picture, media, model or embedded-file field keeps only a `data:` URL of its kind, plus `http(s)` URLs or package paths where the loader itself puts them, and a MIME type field must be well formed. Anything else is left out of that participant's view and reported as a `COLLABORATION_REMOTE_VALUE_REJECTED` slide warning. The next local write removes the value from the room.
- `ooxml-ui/pptx`: `isBrowserOpenableMime(mime)` is replaced by `isBrowserOpenableDataUrl(url)`, which reads the type from the payload URL. `openUrlInNewTab` now opens only a `data:` URL of an inert type (PDF, plain text, CSV, JSON, PNG, JPEG, GIF, WebP, BMP, AVIF) and returns whether it opened a tab. `http(s)`, `blob:` and markup URLs are refused. `downloadDataUrl` ignores anything but `data:` and `blob:` URLs.
- `ooxml-core/collab` and `ooxml-ui/pptx`: the collaboration leave `postMessage` is obeyed only when the embedding window, or the frame itself, sends it from the frame's own origin.
- `ooxml-core/collab`: an update that holds more than one struct per 4 bytes, or more than one deleted range per 2 bytes, is refused before it is decoded. The budget grows with the update, so the first sync of a real document of any size stays under half of it (the densest measured, an Excel sheet of boolean cells, spends 8.6 bytes per struct). Every transport provider and the Teams server apply it. `DEFAULT_UPDATE_LIMITS` is replaced by `defaultUpdateLimits(bytes)`, `MIN_BYTES_PER_STRUCT` and `MIN_BYTES_PER_DELETE_RANGE`.
- `ooxml-core/collab`: a refused update now stops the sync. The provider disconnects with status `error` and emits an `UpdateRefusedError` with a `code` (`too-large`, `malformed`, `server-rejected`, `server-full`), the session reports it as `refusal`, and `collaborationStateOf` includes it. A server close with code 1009 stops the WebSocket transport at once. `ApplyResult` failures carry a `code`, and `guardProviderUpdates`'s `onRejected` receives the `UpdateRefusedError` instead of a string.
- `ooxml-core/opc`: the hyperlink policy now stores every well-formed scheme that is not script-capable, such as `tel:`, `sip:`, `msteams:` and `onenote:`, and still opens only http, https and mailto unless a host opts in. The `unsupported-scheme` rejection reason is gone. Excel's Insert Link accepts these addresses, as Excel does.
- `openteams-server`: the largest sync message defaults to 32 MiB or a 64th of the heap, whichever is smaller (8 MiB on a 512 MiB heap).

## Migration

- If your page embeds a viewer from another origin and posts the leave message, list your page's origin in the new `leaveMessageOrigin` option: `CollaborationConfig.leaveMessageOrigin` for PowerPoint, or `teardown.leaveMessageOrigin` for a `createCollabSession`.
- If you called `isBrowserOpenableMime(element.oleEmbeddedMimeType)`, call `isBrowserOpenableDataUrl(element.oleEmbeddedData)` instead.
- If you open embedded payloads yourself, use `openOrDownloadPayload(url, fileName)`. It downloads anything a tab may not open.
- To set an absolute update limit instead of the proportional one, pass `maxStructs` and `maxDeleteRanges` in `applyUpdateSafe` options, or `maxUpdateStructs` (`TEAMS_MAX_UPDATE_STRUCTS`) on `openteams-server`.
- If you matched collaboration errors by their message, test `isUpdateRefusal(error)` and read `error.code`; `error.message` is the sentence to show, translated by `translateCollabText` in `ooxml-core/i18n`.
- If a host page handled `HyperlinkRejection` values, drop the `unsupported-scheme` case.
- A server that runs with a small heap and hosts very large documents needs a larger heap, or `maxSyncBytes` set explicitly, to keep accepting their first sync: the default takes a 64th of the heap, and applying a dense first sync needs up to about 35 MiB of memory per MiB of message.

## Added

- `ooxml-core/opc`: `safeIdToken` and `isSafeIdToken` next to `partNameToken`. `isAllowedResourceUrl`, `parseDataUrlHeader`, `isBrowserOpenableDataUrl`, `isBrowserOpenableType`, `normalizeMimeType` and `isWellFormedContentType` hold the resource URL rules for every format.
- `ooxml-core/collab`: `scanUpdate` and `defaultUpdateLimits` count, without decoding, what an update would allocate. `guardProviderUpdates` puts that check in front of a y-websocket provider, and `adaptYjsProvider` applies it automatically.
- `ooxml-ui/pptx`: `openOrDownloadPayload`, `createRemoteValueNotifier`, `remoteValueWarnings` and `collaborationRefusalToast`; the collaboration session controller reports `refusal` and calls `onRefused`.
- `ooxml-core/collab`: `UpdateRefusedError`, `isUpdateRefusal`, `LeftOutValue` and `LEFT_OUT_MESSAGE`; `bindWorkbookSession` takes `onLeftOut`, and `readSharedWorkbook` adds a warning when values were left out.
- `ooxml-core/i18n`: `collabStrings` and `translateCollabText`, the refusal and left-out sentences in English, French, German, Spanish, Simplified Chinese, Japanese and Korean. Any tag of those languages finds its sentences (`zh`, `zh-Hans` and `zh_CN` read Simplified Chinese, `de-AT` reads German); Traditional Chinese and other languages read English.
- `ooxml-core/opc`: `pictureUrl` and `mayUseOriginBlobUrl`.
- `ooxml-ui/xlsx`, `ooxml-ui/docx`, `ooxml-ui/visio`, `ooxml-ui/teams` and every PowerPoint viewer: when sharing stops because an update was refused, the user sees why in the display language (a toast in Excel and PowerPoint, `document-error` in Word and Visio, a notice in Teams). Excel also says once per session when content a collaborator sent was left out.
- `openteams-server`: the `maxUpdateStructs` option and `TEAMS_MAX_UPDATE_STRUCTS`.
- `pptx-react-viewer`, `pptx-vue-viewer`, `pptx-angular-viewer`, `pptx-svelte-viewer`, `pptx-vanilla-viewer` and `pptx-viewer-locales`: a toast, in every locale, when content a collaborator sent was left out.

## Security

- Every PowerPoint viewer: a collaboration participant could put a script or markup payload in an embedded object, so that another participant who opened it ran script in the viewer's origin. Peer values are now checked before they reach the deck. The Open button and every binding's OLE action read the type from the payload itself, and open only inert types.
- `ooxml-core/collab` and `openteams-server`: one small update from a signed-in user could make the server or a browser allocate millions of objects and stop. Such updates are now refused before they are decoded.
- `ooxml-ui/docx`: a picture's object URL now always has an image type, so a type a peer claims cannot make it open as markup, and placeholder sizes can no longer add style text.
- `ooxml-core/xlsx`: a hyperlink a peer shares keeps every target the loader keeps and leaves out only a script or disguised one, and the left-out value is reported instead of dropped silently.
- `ooxml-ui/docx`, `ooxml-ui/xlsx`, `ooxml-ui/visio` and `ooxml-core/pptx`: SVG pictures are shown from `data:` URLs instead of object URLs of the application's origin, so opening one in its own tab can no longer run document-controlled script in that origin. Raster pictures keep object URLs.
- `ooxml-core/visio`: a peer can no longer replace an arbitrary package part through shared media, or add markup to the content types part.
- Any page could post the leave message to a viewer frame and drop it from its room. The message must now come from the embedding page.

## Fixed

- `ooxml-core/xlsx`: a collaborator now receives `tel:`, `sip:`, `msteams:`, `onenote:` and other hyperlink targets a workbook holds, which were dropped from shared workbooks.
- `ooxml-core/collab` and `openteams-server`: the update limit no longer refuses the first sync of a large legitimate workbook (it refused one of about 500,000 mixed cells before).
- Every PowerPoint viewer: a joiner whose update from the room was refused no longer stays silently unsynced; it stops with a translated message.
- `ooxml-ui/docx`, `ooxml-ui/xlsx`: a refused update is explained in the display language instead of a raw English reason; `openteams-server` refusals no longer reach a Teams user as a bare close code, and the client no longer reconnects in a loop after one.
