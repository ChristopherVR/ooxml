# Faster, bounded Word and PowerPoint loading and saving

Packages: `ooxml-core` (`ooxml-core/docx`, `ooxml-core/pptx`, `ooxml-core/xlsx`, `ooxml-core/opc`, `ooxml-core/chart`), and the viewers that load documents through it.

## Breaking

- `PptxChartData.embeddedWorkbookData`, the parsed rows of a chart's embedded workbook, is set only when the load needed them: when the chart part caches no categories, no series values or no scatter x values, or when a date axis has no `c:date1904`. Other charts no longer carry it.

## Migration

- To read the rows of any chart's embedded workbook, pass `chartData.externalData.embeddedWorkbookData` (the workbook bytes, still set) to `parseEmbeddedXlsx`.
- Treat Word style catalogs (`paragraphStyles`, `characterStyles`, `tableStyles`) as values. Inheritance is resolved once per `styles` record, so change a style by replacing the record and the style, as the editor's numbering edits do, not by changing a style object in place.

## Added

- `loadDocx` and `loadDocument` take a `limits` option (`DocxLoadLimits`): the compressed package size, the number of parts, the inflated size of one part and of all parts, and the size of `word/document.xml`, which was fixed at 25 MiB. The defaults are unchanged and exported as `DEFAULT_DOCX_LOAD_LIMITS`. A value that is not a positive finite number throws a `RangeError`. Saving reopens the package under the limits it was loaded with.

## Performance

- Saving a Word document no longer moves blocks that did not change. Save time per block now stays level as documents grow: an edit to a 20,000-block document saves in about 2.5 s instead of about 17 s, and inserting, deleting or moving a paragraph costs the same as editing one. The saved document is the same as before, byte for byte.
- Loading a Word document walks `document.xml` once for every unsupported feature it reports instead of once per feature, and copies the loaded model once instead of twice. Saves no longer copy it again.
- Word style inheritance is resolved once per catalog, so a long `basedOn` chain no longer makes loading quadratic or slows each paragraph and run as it is laid out.
- PowerPoint's check for unchanged slides hashes a structure the slide shares by reference once instead of once per path. A one-slide SmartArt deck that took about 6 s to load and 6 s to save now takes well under a second.
- PowerPoint reads the package's relationships once per load for every chart's label check instead of once per chart, and no longer packages a rewritten workbook to make that check. Embedded workbooks are parsed only when a chart needs their rows.

## Security

- Scans of raw XML that ran in time quadratic in the number of empty or unclosed elements are now linear: PowerPoint custom geometry and SmartArt text order, Excel header and footer pictures, and the declared-font scan every product runs before parsing a file. A few kilobytes of such elements could block a load for a minute.

## Fixed

- An empty element no longer swallows the element after it in those scans. SmartArt text whose paragraph or run list held an empty element could lose its order, and a Word font listed before an embedded font was treated as embedded, so its web font was not requested.
