## Breaking

- `ooxml-core/pptx` and `pptx-viewer-core`: `PptxChartData.embeddedWorkbookData`, the parsed rows of a chart's embedded workbook, is set only when the load needed them. That is when the chart part caches no categories, no series values or no scatter x values, or when a date axis has no `c:date1904`. Other charts no longer carry it.

## Migration

- `ooxml-core/pptx` and `pptx-viewer-core`: to read the rows of any chart's embedded workbook, pass `chartData.externalData.embeddedWorkbookData` (the workbook bytes, still set) to `parseEmbeddedXlsx`.
- `ooxml-core/docx` and `docx-core`: treat Word style catalogs (`paragraphStyles`, `characterStyles`, `tableStyles`) as values. Inheritance is resolved once per `styles` record, so change a style by replacing the record and the style, as the editor's numbering edits do, not by changing a style object in place.

## Added

- `ooxml-core/docx` and `docx-core`: `loadDocx` and `loadDocument` take a `limits` option (`DocxLoadLimits`). It sets the compressed package size, the number of parts, the inflated size of one part and of all parts, and the size of `word/document.xml`, which was fixed at 25 MiB. The defaults are unchanged and exported as `DEFAULT_DOCX_LOAD_LIMITS`. A value that is not a positive finite number throws a `RangeError`. Saving reopens the package under the limits it was loaded with.

## Performance

- `ooxml-core/docx`, `docx-core` and Word viewers: saving a Word document no longer moves blocks that did not change. Save time per block now stays level as documents grow: an edit to a 20,000-block document saves in about 2.5 s instead of about 17 s, and inserting, deleting or moving a paragraph costs the same as editing one. The saved document is the same as before, byte for byte.
- `ooxml-core/docx`, `docx-core` and Word viewers: loading a Word document walks `document.xml` once for every unsupported feature it reports instead of once per feature, and copies the loaded model once instead of twice. Saves no longer copy it again.
- `ooxml-core/docx`, `docx-core` and Word viewers: Word style inheritance is resolved once per catalog, so a long `basedOn` chain no longer makes loading quadratic or slows each paragraph and run as it is laid out.
- `ooxml-core/pptx`, `pptx-viewer-core` and PowerPoint viewers: the check for unchanged slides hashes a structure the slide shares by reference once instead of once per path. A one-slide SmartArt deck that took about 6 s to load and 6 s to save now takes well under a second.
- `ooxml-core/pptx`, `pptx-viewer-core` and PowerPoint viewers: a load reads the package's relationships once for every chart's label check instead of once per chart, and no longer packages a rewritten workbook to make that check. Embedded workbooks are parsed only when a chart needs their rows.

## Security

- `ooxml-core`, `pptx-viewer-core`, `docx-core`, `@christophervr/xlsx-core`, PowerPoint viewers, Word viewers and Excel viewers: scans of raw XML that ran in time quadratic in the number of empty or unclosed elements are now linear. This covers PowerPoint custom geometry and SmartArt text order, Excel header and footer pictures, and the declared-font scan every product runs before parsing a file. A few kilobytes of such elements could block a load for a minute.

## Fixed

- `ooxml-core`, `pptx-viewer-core`, `docx-core`, PowerPoint viewers and Word viewers: an empty element no longer swallows the element after it in the raw XML scans that run before a file is parsed. SmartArt text whose paragraph or run list held an empty element could lose its order. A Word font listed before an embedded font was treated as embedded, so its web font was not requested.
