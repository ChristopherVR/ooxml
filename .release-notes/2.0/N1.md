## Breaking

- `pptx-viewer-core` and `ooxml-core/pptx`: element ids are now built from an encoded form of the part name. Decks whose slide, layout and master parts use ordinary names (letters, digits, `-`, `.`, `_`, `~`) keep exactly the same ids, such as `ppt/slides/slide1.xml-shape-0`. A part name with any other character, for example a space or a non-ASCII letter, now appears percent-encoded in the id.

## Migration

- If you stored element ids for decks with unusual part names, reload the deck and read the ids again. `PptxSlide.id` is unchanged and is still the part name. Autosaved decks reopen normally; an unsaved inline text draft of such a deck is not reapplied, because its element id no longer matches. Existing collaboration rooms keep the ids already stored in them.

## Added

- `ooxml-core/opc`: `partNameToken` turns a part name into text that is safe to build identifiers from.

## Changed

- `ooxml-ui/pptx`: `escapeCssAttributeValue` and `elementIdSelector` now always produce CSS hex escapes, and no longer depend on `CSS.escape`. The result is still valid inside a double-quoted selector string.

## Security

- `pptx-svelte-viewer`: opening a crafted presentation could run script in the host page, with no click, when the page had no strict script policy. Part names are now encoded before they reach element ids, and the viewer writes every style sheet as text, so a name or id can no longer become markup. Update if you host the Svelte viewer.
- `ooxml-ui/pptx`, `pptx-react-viewer`, `pptx-vue-viewer`, `pptx-svelte-viewer` and `pptx-vanilla-viewer`: element ids are escaped wherever they are placed in a style rule or a selector, including ids received from a collaboration peer.
