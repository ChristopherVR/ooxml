## Breaking

- `ooxml-core/pptx` and `pptx-viewer-core`: element ids are now built from an encoded form of the part name. Decks whose slide, layout and master parts use ordinary names (letters, digits, `-`, `.`, `_`, `~`, with `/` between folders) keep exactly the same ids, such as `ppt/slides/slide1.xml-shape-0`. A part name with any other character, for example a space or a non-ASCII letter, now appears percent-encoded in the id. Placeholders created by a layout switch follow the same rule.
- `ooxml-ui/pptx` and PowerPoint viewers: the ids of generated SVG filters, gradients, markers, patterns and clip paths are now encoded, so most of them change even for ordinary decks. For example, `soft-edge-ppt/slides/slide1.xml-shape-0` becomes `soft-edge-ppt_2f_slides_2f_slide1.xml-shape-0`.

## Migration

- `ooxml-core/pptx`, `pptx-viewer-core` and PowerPoint viewers: if you stored element ids for decks with unusual part names, reload the deck and read the ids again. `PptxSlide.id` is unchanged and is still the part name. Autosaved decks reopen normally. An unsaved inline text draft of such a deck is not reapplied, because its element id no longer matches. Existing collaboration rooms keep the ids already stored in them.
- `ooxml-ui/pptx` and PowerPoint viewers: if your code or styles look up a generated SVG definition by id, get the id from the exported helper for that effect, such as `getSoftEdgeFilterId`, or encode the element id with `svgIdToken`.

## Added

- `ooxml-core/opc`: `partNameToken` turns a part name into text that is safe to build identifiers from.
- `ooxml-ui/pptx`: `svgIdToken` turns any text into a safe part of an SVG id and of the references to it.

## Changed

- `ooxml-ui/pptx`: `escapeCssAttributeValue` and `elementIdSelector` now always produce CSS hex escapes, and no longer depend on `CSS.escape`. The result is still valid inside a double-quoted selector string.

## Fixed

- `ooxml-ui/pptx` and PowerPoint viewers: soft edge, bevel, duotone, picture and other SVG effects now appear on slides whose part name holds a space, a non-ASCII letter or a percent sign.
- `pptx-react-viewer` and `@christophervr/pptx-viewer`: Save as Picture, paste special and ending an animation preview no longer throw for an element id with characters that are special in a selector.

## Security

- `pptx-svelte-viewer`: opening a crafted presentation could run script in the host page, with no click, when the page had no strict script policy. Part names are now encoded before they reach element ids, and the viewer writes every style sheet as text, so a name or id can no longer become markup. Update if you host the Svelte viewer.
- `ooxml-ui/pptx` and PowerPoint viewers: element ids are escaped wherever they are placed in a style rule or a selector.
