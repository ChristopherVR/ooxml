# Signature verification

Packages: `ooxml-core` (`ooxml-core/pptx/signature-node`, `ooxml-core/opc`), `pptx-viewer-core`.

## Breaking

- `verified-trusted` now requires a signature value that verifies, every signed reference verifying, signed references that cover the document content, and a signer certificate that permits document signing and chains to a root you configured.
- No trust roots are built in. The platform's TLS roots are no longer used, so an intact signature reports `verified-untrusted` until `PPTX_VIEWER_TRUST_ROOTS_PEM` or `PPTX_VIEWER_TRUST_ROOTS_FILE` is set.
- Certificates whose extended key usage excludes document signing, such as TLS server certificates, and certificates whose key usage has neither `digitalSignature` nor `nonRepudiation`, are reported as untrusted.
- New status `coverage-incomplete`, on the report and on each signature detail.
- `SignatureDetail` gains the required fields `uncoveredParts` and `coverageGaps`, and `SignatureReferenceCheck.digestStatus` gains `content-type-mismatch`.
- `referenceChecks` is empty unless the signature value verified, and `signingTime` is read only from signed content.
- Removed `verifySignatureValue`, `buildReferenceChecksFromSignatureXml`, `buildReferenceChecksFromPptxViewerManifest` and `PPTX_VIEWER_MANIFEST_NS`. The unsigned manifest extension is no longer read.
- `resolveReferenceUriToPart` and `parseReferenceUri` strip the `?ContentType=` query, keep the percent-encoding of the part name and return `undefined` for URIs that do not name exactly one valid part name. The enveloped signature transform is no longer supported.
- A stored item that no signature covers is reported as `coverage-incomplete` even when no relationship points at it. Document properties, thumbnails, custom XML, presentation and view properties may stay unsigned only in their usual locations.
- `PptxHandler.load` rejects a package that carries a signature when any relationships part has an element outside the OPC namespace, a repeated `Id`, an invalid `TargetMode` or attributes the schema does not allow. Unsigned packages load as before.
- `PPTX_VIEWER_REQUIRE_TIMESTAMP` can no longer be satisfied. Timestamp tokens are not validated, so `evaluateTimestampAuthority` reports `not-checked` for a token instead of `valid`, `invalid` or `error`, and with the variable set every signature reports `timestamp-untrusted`.
- Certificate chains that exceed a `pathLenConstraint` are reported as untrusted.
- Removed `normalizePartPath`. `evaluateSignatureCoverage` no longer takes the signature paths, and `SignaturePackage` gains `namesByKey`.
- `parseRelationshipsPart` moved to `ooxml-core/opc` and is strict: it throws on a part the schema does not allow.

## Migration

- Configure the roots you trust for document signing with `PPTX_VIEWER_TRUST_ROOTS_PEM` or `PPTX_VIEWER_TRUST_ROOTS_FILE`.
- Handle `coverage-incomplete` wherever you handle other non-verified statuses, and read `uncoveredParts` if you need to show which parts a signature leaves out.
- Remove `PPTX_VIEWER_REQUIRE_TIMESTAMP` unless you want every signature rejected until timestamp validation exists.
- Replace `verifySignatureValue` with `parseXmlSignature` followed by `verifySignedInfo`, and the removed reference builders with `checkSignedReferences`.

## Added

- `ooxml-core/opc` exports `partNameKey`, `isPartName`, `asciiLowerCase`, `parseRelationshipsPart` and `canonicalRelationshipsXml`.
- Signatures in the layout Office writes now verify: `SignedInfo` references to `Object` elements, `Manifest` references, `?ContentType` binding and the OPC relationships transform.

## Security

- References are taken only from the verified `SignedInfo` and from `Manifest` elements it protects, so content outside the signature can no longer influence the result.
- Signatures with repeated, misplaced or ambiguous structure, duplicate `Id` values or document type declarations are rejected.
- A relationship or relationships part added beside signed content is reported instead of being ignored.
- Revocation requests are sent only for certificates that verified a signature value.
- The verifier and `PptxHandler.load` read relationships through one strict reader, so a signed package cannot show relationships its signature check did not see.
- Part names compare as ECMA-376 Part 2 requires, so case variants and percent-encoded variants of a part are no longer overlooked.
- Unsigned relationships are exempted by exact type, and only for targets in the usual locations.
- Signatures written by `signPptxWithCertificate` bind each part to its content type and no longer reference `[Content_Types].xml`.

## Fixed

- `contentTypeForPart` matches `Override` part names ASCII case-insensitively and reads the extension from the last path segment only.
- Signature references to parts whose names contain percent-encoding, such as `a%20b.xml`, now resolve.
