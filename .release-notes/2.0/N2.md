## Breaking

- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: the status `verified-trusted` now requires a signature value that verifies, every signed reference verifying, signed references that cover the document content, and a signer certificate that permits document signing and chains to a root you configured.
- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: no trust roots are built in. The platform's TLS roots are no longer used, so an intact signature reports `verified-untrusted` until `PPTX_VIEWER_TRUST_ROOTS_PEM` or `PPTX_VIEWER_TRUST_ROOTS_FILE` is set.
- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: certificates whose extended key usage excludes document signing are reported as untrusted, so a signature stays `verified-untrusted` at best. This includes TLS server certificates and signers whose certificate lists only `clientAuth` or only `codeSigning`. Certificates that also list `emailProtection`, document signing or `anyExtendedKeyUsage` are accepted. Certificates whose key usage has neither `digitalSignature` nor `nonRepudiation` are also reported as untrusted.
- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: a new status, `coverage-incomplete`, on the report and on each signature detail.
- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: `SignatureDetail` gains the required fields `uncoveredParts` and `coverageGaps`, and `SignatureReferenceCheck.digestStatus` gains `content-type-mismatch`.
- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: `referenceChecks` is empty unless the signature value verified, and `signingTime` is read only from signed content.
- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: removed `verifySignatureValue`, `buildReferenceChecksFromSignatureXml`, `buildReferenceChecksFromPptxViewerManifest` and `PPTX_VIEWER_MANIFEST_NS`. The unsigned manifest extension is no longer read.
- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: `resolveReferenceUriToPart` and `parseReferenceUri` strip the `?ContentType=` query, keep the percent-encoding of the part name and return `undefined` for URIs that do not name exactly one valid part name. The enveloped signature transform is no longer supported.
- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: a stored item that no signature covers is reported as `coverage-incomplete` even when no relationship points at it. Document properties, thumbnails, custom XML, presentation and view properties may stay unsigned only in their usual locations, whether or not the relationship to them is signed.
- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: `computeDetailStatus` and `computeVerificationStatus` decide integrity first. A failed signature value, reference or coverage check now outranks certificate, revocation, timestamp and policy statuses, for each signature and across the package, so some packages report a different status than before.
- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: `signPptxWithCertificate` returns `success: false` and no `signedData` for a stored item whose name is not a valid part name, for a relationships part the strict reader rejects, and for output whose signature does not verify and cover its content. It used to return `success: true` for these. Trust and policy outcomes do not fail signing.
- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: `PPTX_VIEWER_REQUIRE_TIMESTAMP` can no longer be satisfied. Timestamp tokens are not validated, so `evaluateTimestampAuthority` reports `not-checked` for a token instead of `valid`, `invalid` or `error`, and with the variable set every signature reports `timestamp-untrusted`.
- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: certificate chains that exceed a `pathLenConstraint` are reported as untrusted.
- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: removed `normalizePartPath`. `evaluateSignatureCoverage` no longer takes the signature paths, and `SignaturePackage` gains `namesByKey`.
- `ooxml-core/opc`, `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: `parseRelationshipsPart` moved to `ooxml-core/opc` and is strict: it throws on a part the schema does not allow. It accepts an empty `Target` and `Id`s that differ only in case, which the schema allows.

## Migration

- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: configure the roots you trust for document signing with `PPTX_VIEWER_TRUST_ROOTS_PEM` or `PPTX_VIEWER_TRUST_ROOTS_FILE`.
- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: handle `coverage-incomplete` wherever you handle other non-verified statuses, and read `uncoveredParts` if you need to show which parts a signature leaves out, including custom XML.
- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: check `success` from `signPptxWithCertificate` before using its result, and rename stored items that are not valid part names before signing.
- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: reissue signing certificates that list only `clientAuth` or only `codeSigning` if their signatures must report `verified-trusted`.
- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: remove `PPTX_VIEWER_REQUIRE_TIMESTAMP` unless you want every signature rejected until timestamp validation exists.
- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: replace `verifySignatureValue` with `parseXmlSignature` followed by `verifySignedInfo`, and the removed reference builders with `checkSignedReferences`.

## Added

- `ooxml-core/opc`: new exports `partNameKey`, `isPartName`, `asciiLowerCase`, `parseRelationshipsPart`, `canonicalRelationshipsXml` and `isRelationshipsItem`.
- `ooxml-core/xml`: new export `withoutByteOrderMark`.
- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: signatures in the layout Office writes now verify: `SignedInfo` references to `Object` elements, `Manifest` references, `?ContentType` binding and the OPC relationships transform.

## Security

- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: references are taken only from the verified `SignedInfo` and from `Manifest` elements it protects, so content outside the signature can no longer influence the result.
- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: signatures with repeated, misplaced or ambiguous structure, duplicate `Id` values or document type declarations are rejected.
- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: a relationship or relationships part added beside signed content is reported instead of being ignored.
- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: revocation requests are sent only for certificates that verified a signature value.
- `ooxml-core/pptx`, `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: the verifier and `PptxHandler.load` read relationships through one strict reader, so a signed package cannot show relationships its signature check did not see. The Word and Excel loaders are not bound to this reader.
- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: a revocation or timestamp policy can no longer replace an integrity failure, or make a package with one report `verified-untrusted`.
- `ooxml-core/opc`, `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: part names compare as ECMA-376 Part 2 requires, so case variants and percent-encoded variants of a part are no longer overlooked.
- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: unsigned relationships are exempted by exact type, and only for targets in the usual locations.
- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: signatures written by `signPptxWithCertificate` bind each part to its content type and no longer reference `[Content_Types].xml`.

## Fixed

- `ooxml-core/opc`: `contentTypeForPart` matches `Override` part names ASCII case-insensitively and reads the extension from the last path segment only.
- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: signature references to parts whose names contain percent-encoding, such as `a%20b.xml`, now resolve.
- `ooxml-core/xml`, `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: XML parts that start with a UTF-8 byte order mark now parse in `parseXml` and in signature verification, so signed decks whose relationships or signature parts have one open and verify, and such decks can be signed.
- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: a signed relationship to custom XML or another part a signature may leave out no longer makes a genuine signature `coverage-incomplete`.
- `ooxml-core/pptx/signature-node` and `pptx-viewer-core`: `signPptxWithCertificate` removes earlier signature parts in any letter case and keeps one origin relationship when a package is signed again.
