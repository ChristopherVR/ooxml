## Breaking

- `ooxml-ui/pptx` and every PowerPoint binding (`@christophervr/pptx-viewer`, `pptx-vue-viewer`, `pptx-angular-viewer`, `pptx-svelte-viewer`, `pptx-vanilla-viewer`): external links in a deck always open in a new tab with `noopener` and `noreferrer`. The deck's target frame (`tgtFrame`) is still saved back unchanged, but no longer decides where a link opens. `file:` and `ftp:` links stay in the deck and are no longer opened.
- `ooxml-ui/pptx`: `resolveHyperlinkTargetAttrs` is removed, and `safeOpenUrl` and `openExternalHyperlinkConfirmed` no longer take a target argument.
- OOXML Office suite: `collaboration.token` in `ai-config.json` (or `globalThis.ooxmlAiConfig`) is ignored. A deployment that synced shared chats with a fixed token now serves short-lived tokens from its own endpoint and names it in `collaboration.credentialsUrl`.
- OOXML Office suite: AI keys are kept for the current tab only. The "Remember the key on this device" option is gone, and keys an earlier version remembered are deleted when the app loads, so users enter them again once per tab.

## Migration

- If your code called `resolveHyperlinkTargetAttrs`, use `target="_blank"` and `rel="noopener noreferrer"`. Drop the target argument from `safeOpenUrl` and `openExternalHyperlinkConfirmed` calls.
- For shared-chat sync, add an endpoint that returns `{ "token": "...", "expiresAt": "<ISO time>" }` for the signed-in user, set `collaboration.credentialsUrl` to it, and remove `collaboration.token`. The suite calls it with the user's cookies before every connection. See `docs/suite-ai-config.md`.
- Hosts that put a page on the same origin as the suite should give it the policy in `scripts/csp.mjs`, or move it to another origin.

## Added

- `ooxml-core/teams`: `createSyncTransport` and `createSharedChat` accept an asynchronous `token` source that is asked for a fresh token before every connection attempt.

## Security

- Every page published on the GitHub Pages site (the suite, its 404 page, and each viewer's documentation and framework demos) and the desktop app now carry the same Content Security Policy, from one source. It allows script only from the site itself and never inline, so script injected into any one page cannot reach the suite's stored documents. The site build fails on a page without the policy.
- The policy now allows what the editors need: fonts embedded in a document (`blob:`), reading back `blob:` and `data:` URLs, and the YouTube and Vimeo players for online video in decks. Other websites are not framed, so a Teams website tab in the suite offers "Open externally" instead.
- The suite's service worker serves a saved file only while it matches the SHA-256 recorded at build time. A changed copy is deleted and fetched again from the site, and the caches of older builds are dropped. The shell's script and style tags carry subresource integrity.
- The desktop app's window stays on the bundled app. Web and `mailto:` links open in the system browser or mail client; other destinations and new in-app windows are refused.
