## Breaking

- `ooxml-ui/pptx` and every PowerPoint binding (`@christophervr/pptx-viewer`, `pptx-vue-viewer`, `pptx-angular-viewer`, `pptx-svelte-viewer`, `pptx-vanilla-viewer`): external links in a deck always open in a new tab with `noopener` and `noreferrer`. The deck's target frame (`tgtFrame`) is still saved back unchanged, but no longer decides where a link opens. `file:` and `ftp:` links stay in the deck and are no longer opened. Relative links (a path with no scheme, such as `notes.html` or `#part`) also stay in the deck and no longer open unless the host opts in.
- `ooxml-ui/pptx` and every PowerPoint binding: `CollaborationSessionState` and `CollaborationShellState` gain a required `failure` field, which matters only to hosts that build these objects themselves. The React `StartSessionForm` prop `connectionFailed` becomes `connectionFailure`, a translation key.
- `ooxml-ui/pptx`: `resolveHyperlinkTargetAttrs` is removed, and `safeOpenUrl` and `openExternalHyperlinkConfirmed` no longer take a target argument.
- OOXML Office suite: `collaboration.token` in `ai-config.json` (or `globalThis.ooxmlAiConfig`) is ignored. A deployment that synced shared chats with a fixed token now serves short-lived tokens from its own endpoint and names it in `collaboration.credentialsUrl`.
- OOXML Office suite: AI keys are kept for the current tab only. The "Remember the key on this device" option is gone, and keys an earlier version remembered are deleted when the app loads, so users enter them again once per tab.
- `ooxml-core/collab`, `ooxml-ui/pptx` and every PowerPoint binding: a serverless (peer-to-peer) Share or Broadcast session is keyed by a random secret that its invitation link carries after `#key=`. Invitation and broadcast links made by an earlier version, and bare room codes without a server, no longer join; start a new session and send its new link. A `CollaborationConfig` with `transport: 'webrtc'` (or a blank `serverUrl`) must carry `secret`, and `authToken` is no longer used as the peer-to-peer password. `buildBroadcastViewerUrl` takes the session's config instead of a room id and server URL, and `buildQueryLinkUrl` and `buildShareUrl` (in `ooxml-ui/pptx` and `pptx-angular-viewer`) are removed.
- `ooxml-core/collab`: `parseShareInvitation` is replaced by `readShareInvitation`, which returns `{ kind: 'session', target }`, `{ kind: 'missing-secret', roomId }` or `{ kind: 'none' }` instead of a target or `null`.
- `ooxml-ui`: `OfficeShareDialogLabels` gains a required `missingKey` caption, which matters only to code that builds a complete labels object.

## Migration

- If your deck links point at pages beside the host page and should keep opening, call `setOpenRelativeHyperlinks(true)` from `ooxml-ui/pptx` once at startup. It applies to every viewer on the page, and the links resolve against the host page's address.
- If your code called `resolveHyperlinkTargetAttrs`, use `target="_blank"` and `rel="noopener noreferrer"`. Drop the target argument from `safeOpenUrl` and `openExternalHyperlinkConfirmed` calls.
- For shared-chat sync, add an endpoint that returns `{ "token": "...", "expiresAt": "<ISO time>" }` for the signed-in user, set `collaboration.credentialsUrl` to it, and remove `collaboration.token`. The suite calls it with the user's cookies before every connection. See `docs/suite-ai-config.md`.
- Hosts that put a page on the same origin as the suite should give it the policy in `scripts/csp.mjs`, or move it to another origin.
- Create peer-to-peer sessions with `buildCreateCollaborationConfig` or `buildBroadcastConfig`, which add the secret (or call `createShareSecret` from `ooxml-core/collab`), and build their links with `buildCollaborationShareUrl` or `buildBroadcastViewerUrl(config, location)` in place of `buildShareUrl` and `buildQueryLinkUrl`. If you build a join config yourself, read the link with `readShareInvitation` and, when its `kind` is `'session'`, pass `target.secret`.
- Replace `parseShareInvitation(link)` checks with `readShareInvitation(link)`: test `invitation.kind === 'session'` and read `invitation.target`. A `'missing-secret'` result is a peer-to-peer link without its key; tell the user to ask for a new link.

## Added

- `ooxml-core/teams`: `createSyncTransport` and `createSharedChat` accept an asynchronous `token` source that is asked for a fresh token before every connection attempt.
- `ooxml-core/collab`: `createShareSecret`, `isValidShareSecret` and `webrtcRoomName` for peer-to-peer sessions, and a `param` argument on `shareInvitation` and `readShareInvitation` for broadcast links (`broadcast`) beside room links (`room`).
- `ooxml-ui/pptx`: `shareFormFailureKey(form, sessionFailureKey)`, the translation key of the reason a Share dialog's form shows above its fields.
- `ooxml-ui/pptx`: `setOpenRelativeHyperlinks(enabled)`, the opt-in for opening relative deck links.
- `ooxml-ui/pptx` and every PowerPoint binding: a collaboration session that cannot start now says why, in the viewer's language, in the Share dialog and as the status tooltip, instead of only "Connection error": for example a peer-to-peer link without its session key, a page not served over https, a blocked `ws://` server or a server that cannot be reached. Custom shells get the reason as the new `failure` field of `shellState`, and `collaborationFailureMessageKey` maps it to a translation key.

## Security

- Every page published on the GitHub Pages site (the suite, its 404 page, and each viewer's documentation and framework demos) and the desktop app now carry the same Content Security Policy, from one source. It allows script only from the site itself and never inline, so script injected into any one page cannot reach the suite's stored documents. The site build fails on a page without the policy.
- The policy now allows what the editors need: fonts embedded in a document (`blob:`), reading back `blob:` and `data:` URLs, and the YouTube and Vimeo players for online video in decks. Other websites are not framed, so a Teams website tab in the suite offers "Open externally" instead.
- The suite's service worker serves a saved file only while it matches the SHA-256 recorded at build time. A changed copy is deleted and fetched again from the site. The shell's script and style tags carry subresource integrity.
- A new version of the suite installs only when every file it downloads matches its recorded hash, so a cache or edge still serving the previous deploy can no longer leave a version without its shell; the working version stays and the next update check tries again, keeping what the failed attempt already saved. After an update, a window still running the previous version keeps loading that version's files, checked against that version's own hashes, so opening another kind of file there still works, online or offline. The previous version's cache is deleted once no window runs it. A page that loads in the previous version while the new one installs no longer deletes the new version's cache, and the worker keeps a record only for windows and workers that are still open or started in the last minute, so one that opens while another page loads keeps its version's files. Caches from versions before 2.0 cannot be checked and are dropped at the update.
- The PowerPoint framework demos keep an AI key set by hand for the current tab only (sessionStorage) and delete any key an earlier demo version left in localStorage.
- The desktop app's window stays on the bundled app. Web and `mailto:` links open in the system browser or mail client; other destinations and new in-app windows are refused.
- PowerPoint peer-to-peer sessions no longer show the room to the public signaling server. It sees only a SHA-256 hash of the session secret and signaling messages encrypted with that secret, so knowing or guessing a room name is no longer enough to join. The secret travels only in the link's fragment, which browsers never send to a server.

## Fixed

- The published Angular demos of PowerPoint, Word, Excel, Visio and Teams, and the Angular modes of the Word and Excel demos, are compiled ahead of time, so they run under the site's script policy instead of staying blank.
- `ooxml-ui` and every PowerPoint binding: a peer-to-peer invitation without its session key, including older links that carried the key in the query, now says why it cannot be joined, in the viewer's language, instead of only disabling Join. Opening such a link as the page address shows "Connection error" with Retry in the status bar of every binding, with the reason as its tooltip, without opening Share first, and the reason in the Share dialog. The Angular viewer gains that status bar pill, which the other bindings already had. The shared Share dialog of Word, Excel and Visio shows the same caption.
