## Security

- Every published package (`ooxml-core`, `ooxml-ui`, `ooxml-mcp` and the viewer packages) is now released by a pipeline in which no third-party code can push to the repository or create releases. The install, the build, the smoke tests and the changelog generator run with a read-only token, and the job that commits, tags and creates the GitHub releases runs only GitHub's own tools and the repository's dependency-free release scripts. A workflow check enforces this for every workflow.
- The changelog generator and the preview publisher are now pinned in the lockfile with their integrity hashes, instead of being downloaded by name at run time.
- The signed tarballs attached to each GitHub release are checked against the integrity the npm registry records before they are uploaded.
- Preview packages are published automatically only for pull requests from this repository's own branches. A pull request from a fork gets preview packages only after a maintainer reviews it and adds a label.
- The development tool chain no longer resolves versions of `glob` and `minimatch` with known advisories. This does not change what the published packages depend on.
