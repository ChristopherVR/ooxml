## Breaking

- `ooxml-core`, `openteams-server` and the OpenTeams bindings move to Teams protocol version 2. Deploy the app and the server together: a server closes clients that announce another version, with a message that names both versions.
- `ooxml-core/teams`: a new 1:1 chat id is `dm-` and 32 hex digits, and a new group chat id is `g-` with a random part bound to its creator. Meeting chats are group chats and no longer use `mt-<meeting id>`.
- `ooxml-core/teams`: `meetingChatId` is removed, and `createGroup` no longer takes an `id`. Read a meeting's chat from `meeting.chatId`.
- `validateTeamsUpdate` now checks the `teams:chats` directory, and no longer lets the first writer fill an empty `teams:chat-members` map. A server that uses it must seed new chat rooms itself, as `openteams-server` does.
- `openteams-server`: `?members=` no longer sets the members of a new room. It is read only for a 1:1 room, to check the two people against the chat id.
- `openteams-server`: rooms, file scopes and uploader records are stored under new names (`=` and the base32 of the exact name). An older server cannot read a migrated data directory.
- `ooxml-core/teams`: a group's directory row keeps the `members` it was created with, and later changes are one `member:<user id>` field per person. `validateTeamsUpdate` can now answer `{ ok: true, reverts }`: a server that uses it must apply the update and then call the new `applyUpdateReverts(doc, reverts)`.
- `ooxml-core/teams`: `createChatRooms` passes `openRoom` a third argument, `onSynced`, and takes an optional `directorySync`. The handle `openRoom` returns must now have `synced()`, and the result has `leavingChats()`.
- `ooxml-core/teams`: a server using `validateTeamsUpdate` must apply the update and `applyUpdateReverts` in one transaction whose origin is not the sender's connection, so that a failure or a concurrent reader never sees the update without its reverts.
- `openteams-server`: a sync message that cannot be read or applied now closes its socket with `1008 update rejected: invalid-update`. It used to be logged and dropped.
- `ooxml-core/teams`: local snapshots are kept per protocol version, so changes that were still unsent when the app was upgraded are discarded.

## Migration

- Back up the data directory, then start the new `openteams-server` once. It renames existing rooms, files and uploader records itself, and continues on the next start if it is interrupted.
- Existing chats keep working for the people their rooms list, and 1:1 chats keep their history. A chat that never got a room on the server under an old id cannot be started any more: start a new one.
- The migration cannot tell who should be in an existing room. If you suspect someone joined a private chat without being invited, check that room's member list.
- Data stored under a chat id that only 2.0 issues cannot be genuine, so the migration does not turn it into that chat. It moves to a `.quarantine` folder inside `rooms`, `files` or `file-meta`, and the server logs each entry. Review or delete those folders; the server never reads them.
- If you run your own server on `validateTeamsUpdate`, follow the private chat rules in `docs/teams-area.md`.

## Fixed

- People added to or leaving a group at the same time are all kept, on every client. These changes no longer overwrite each other, and they can no longer stop a person's workspace sync.
- A change made offline by someone who has since been removed from a group is undone by the server instead of stopping that person's sync.
- If a group's creator closes the app right after creating it, the people listed are let into the chat the next time the creator opens it.
- Leaving a group while offline now takes effect in the chat itself when the app next connects, even if it was closed in between. The server used to keep admitting that person.
- `validateTeamsUpdate` no longer throws on a value it cannot compare. A stored big integer no longer blocks changes to its row, and writing a new one is refused as `malformed-row`.

## Security

- Private chat membership is now decided by the server. Editing the chat directory no longer gets anyone into a chat: only a chat's members can change its row, a chat's kind and creator are fixed, and clients no longer copy the directory into the room's member list.
- Nobody can take over a chat room by connecting first. A 1:1 room can be created only by its two people and a group room only by its creator, and a room that has been emptied stays closed.
- A member can no longer remove someone else from a chat by setting their entry to `false`.
- On disks that ignore letter case, an upper-case spelling of a private chat's name no longer reaches that chat or its files. Room and scope names that differ only by case are now kept apart.
- Data prepared on an older server under the name of a future private chat no longer becomes that chat when the server is upgraded.
- `openteams-server` applies an update and the corrections it needs as one step. If checking or applying fails, nothing is stored or sent to anyone, and the sender's connection closes. Nothing a connection sends after being refused is applied.
