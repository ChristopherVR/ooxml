## Breaking

- `ooxml-core/pptx`, `ooxml-ui/pptx`, PowerPoint viewers: a shared presentation now carries its pictures and media. The writers never put a page-local `blob:` URL in the room: each is written as a media token (`ooxml-media:<id>`) and its bytes go once into the new `pptx:media` map, which every participant turns into URLs of its own page. `readSlidesFromYDoc` and `readSlideFromYMap` resolve the tokens, keep a token whose bytes have not arrived (it draws nothing until they do), and refuse a raw `blob:` URL a peer wrote with a `COLLABORATION_REMOTE_VALUE_REJECTED` warning. A viewer from before 2.0 in the same room shows those pictures as broken, so every participant of a room must use 2.0.

## Migration

- `ooxml-core/pptx`, `ooxml-ui/pptx`: if you write PowerPoint slides into a room yourself and your slides name embedded audio or video only by part (`mediaPath`), call `configureCollaborationMedia(doc, { localMediaUrl })` with a function that returns the URL your page plays each part from, so the room can carry its bytes.

## Added

- `ooxml-core/pptx`, `ooxml-ui/pptx`: `configureCollaborationMedia`, `collaborationMedia`, `YDOC_MEDIA_KEY`, `MAX_SHARED_MEDIA_BYTES` (16 MiB) and `MAX_PEER_TO_PEER_MEDIA_BYTES` (128 KiB), and the `COLLABORATION_MEDIA_WITHHELD` slide warning for a picture or video too large to share, which every viewer shows as a notice in each of its languages.
- `ooxml-core/opc`: `resourceKindAccepts(kind, mime)`.
- `ooxml-ui/pptx`: `createBroadcastFollower` and `broadcastFollowSlide`, the one rule every binding uses for a broadcast audience to follow the presenter; `RoomJoinTracker` gains `loaded` and `mayWrite`.

## Fixed

- PowerPoint viewers: people who join a shared presentation see its pictures, picture fills, poster frames and embedded video, not only its text, in every binding. The sharer's page puts the bytes in the room, and a joiner without the file shows them from URLs of its own page. A room holds at most 16 MiB of such files (128 KiB in a peer-to-peer session, whose first message to a joiner must fit one WebRTC data channel message); a larger file is left out and the joiners are told why.
- PowerPoint viewers: someone who opens a shared-session link before the sharer's deck reaches the room no longer replaces that deck with a blank one. A session joined with `sessionIntent: 'join'` waits for the room's slides, or for the user to open a file, before it writes its own.
- `pptx-react-viewer`, `pptx-svelte-viewer`, `pptx-vanilla-viewer`: the audience of a live broadcast now follows the presenter's slide. React stopped sending the presenter's slide once the slide show started, and Svelte and vanilla did not follow at all.
- `pptx-svelte-viewer`: a viewer that joins a shared session can reach every slide of the room's deck, not only the first.
- `pptx-vanilla-viewer`: the Broadcast dialog opens with a fresh session name, so Start Broadcast works at once, and the Share and Broadcast fields are labelled for assistive technology.
- `pptx-angular-viewer`: linked YouTube and Vimeo videos show their player after Enable Content. Before, the viewer failed while drawing them and showed nothing.

## Security

- PowerPoint viewers: a picture received from a shared session is shown from a `blob:` URL only for raster images, audio and video; anything else, SVG included, gets a `data:` URL, so it never runs in the application's origin. Linked pictures and media are never fetched by the sharer to be sent on: they stay links, and each participant's browser requests them only after that participant chooses Enable Content.
