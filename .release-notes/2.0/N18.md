## Breaking

- `ooxml-core/pptx` and every PowerPoint viewer: a shared session now carries the deck's pictures and media. A page-local `blob:` URL is never written into the room: it is written as a media token (`ooxml-media:<id>`) and its bytes go once into the new `pptx:media` map, which every participant turns into URLs of its own. `readSlidesFromYDoc` and `readSlideFromYMap` resolve those tokens, refuse a raw `blob:` URL a peer wrote (a `COLLABORATION_REMOTE_VALUE_REJECTED` warning), and leave out linked `http(s)` pictures and media unless the reader allows external content. A host that reads a room through these functions directly sees no linked pictures until it calls `configureCollaborationMedia(doc, { allowExternalContent: true })`.

## Migration

- If you read PowerPoint slides from a room yourself and want linked pictures shown, call `configureCollaborationMedia(doc, { allowExternalContent: true })` before reading. To share embedded audio and video that your slides name only by part, also pass `localMediaUrl`, which returns the URL your page plays a part from.
- If you imported `isLocalOnlyUrl` from `ooxml-core/pptx/editor/render/collaboration-assets`, it is still exported there.

## Added

- `ooxml-core/pptx` and `ooxml-ui/pptx`: `configureCollaborationMedia`, `collaborationMedia`, `YDOC_MEDIA_KEY`, `MAX_SHARED_MEDIA_BYTES` (16 MiB) and `MAX_PEER_TO_PEER_MEDIA_BYTES` (128 KiB), and the `COLLABORATION_MEDIA_WITHHELD` slide warning for a picture or video too large to share. Every viewer shows it as a translated notice.
- `ooxml-core/opc`: `resourceKindAccepts(kind, mime)`.

## Fixed

- Every PowerPoint viewer (React, Vue, Angular, Svelte and vanilla): people who join a shared presentation see its pictures, picture fills, poster frames and embedded video, not only its text. The sharer's page puts the bytes in the room; a joiner without the file shows them from URLs of its own page. A room holds at most 16 MiB of such files (128 KiB in a peer-to-peer session, whose first message to a joiner must fit one WebRTC data channel message); a larger file is left out and the joiners are told why.

## Security

- Every PowerPoint viewer: linked pictures and media in a shared presentation follow each participant's own "Allow external content" setting. A joiner who blocks external content no longer requests a linked picture the sharer's deck points to, and the sharer never fetches linked content to send it to others. A picture received from the room is shown from a `blob:` URL only for raster images, audio and video; anything else, SVG included, gets a `data:` URL, so it never runs in the application's origin.
