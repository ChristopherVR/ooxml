## Breaking

- `ooxml-core/automation`, `xlsx-viewer-mcp` and `ooxml-mcp`: `xlsx_set_cells`, `xlsx_propose_edits` and `xlsx_apply_proposal` (now schema version 2), and `setXlsxCells`, `applyXlsxEdits`, `proposeXlsxEdits`, `applyXlsxProposal` and `createXlsxFromSheets`, refuse a formula that can reach outside the workbook (such as `WEBSERVICE`, `IMAGE`, `HYPERLINK`, `RTD`, `STOCKHISTORY`, the `CUBE` functions or `PY`), sends cell data to an AI service (`COPILOT`, `TRANSLATE`, `DETECTLANGUAGE`), refers to another workbook or a file path, or cannot be read by the formula parser. The error names the cell. Defined names are checked the same way.
- OOXML Office suite: shared assistant chats now carry only what every participant sees. A shared row holds the message text, the model's label, the names of attached files and the number of proposed edits and new files. Conversations shared with an earlier version show their earlier messages as display only once the room syncs, so their proposals can no longer be applied from the chat. Only the person who asked can create the new files a reply proposes.

## Migration

- A host that writes trusted formulas through the automation functions passes `{ formulas: 'unrestricted' }`, and a host that serves trusted MCP callers registers `createXlsxTools({ formulas: 'unrestricted' })` instead of `xlsxTools`. No tool parameter turns the check off.
- In a shared chat, ask again to get proposals you can apply.

## Added

- `ooxml-core/xlsx`: `formulaPolicyIssue`, `cellInputPolicyIssue` and `RESTRICTED_FORMULA_FUNCTIONS` say why a formula reaches outside the workbook, reading it with the formula parser, so a function passed by name to `MAP`, `LET` or `LAMBDA` or written with a storage prefix is found too.
- `ooxml-core/automation`: `createXlsxTools(options)`, `refusedFormula` and the `XlsxFormulaOptions` type. `readXlsxFilledCells` takes `hidden: 'omit'` to leave hidden sheets, rows and columns out and count them in `hidden`.
- `ooxml-core/ai`, a new subpath with the assistant policy: `normalizeAiPolicy`, `userConnectionRefusal`, `checkAiEndpoint` and `aiFeatureEnabled`.
- OOXML Office suite: the `context.includeHidden` policy setting.

## Changed

- OOXML Office suite: hidden and very hidden sheets and the cells of hidden rows and columns are left out of what the assistant reads, and the reply is told how much was left out, unless the policy sets `context.includeHidden`.
- OOXML Office suite: models a user saved earlier are offered only while the policy still allows their provider in `userProviders` and their endpoint passes the endpoint check.

## Fixed

- OOXML Office suite: a formula the assistant proposes for a new workbook is checked like an edit, and harmless formulas such as `=IF(A1="http",1,0)` or `="a|b"` are no longer rejected.
- OOXML Office suite: while a document shows the assistant's suggestions, Save, Download and the other commands that save it refuse, and a message sent meanwhile reads the file as last saved, so suggestions are never saved or exported before they are applied.

## Security

- OOXML Office suite: a participant in a shared chat could show a proposal whose review differed from the edit it applied, and replies placed the before-and-after text of proposed edits and the attached files' ids in the room. A message someone else wrote is now display only, is never treated as the assistant's own history, and the room never receives proposals, raw replies, file ids or quoted file text. Update if you use shared chats.
- `ooxml-core/automation` and the Excel MCP tools: a prompt-injected model could write a formula that sends workbook data to a server when the file is opened in a spreadsheet application. Such formulas are now refused on every write path.
