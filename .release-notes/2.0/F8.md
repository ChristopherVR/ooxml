## Breaking

- `openteams-server`: a server with an `authorizeSync` hook and no `users` or `authenticate` hook now answers `POST /auth/session`, every `/files/...` request and every `/signal/...` socket with 404. It cannot tell who a request comes from, so it offers sync alone. Pass `insecureDev: true` to open them for development, or add `authenticate`.
- `openteams-server`: the server refuses to start when `TEAMS_SESSION_SECRET` (`sessionSecret`) is set to fewer than 32 characters or to fewer than 8 distinct characters. Leaving it unset still gives a random secret per process.
- `openteams-server`: with accounts, a call signaling socket may speak only as its signed-in user. A signal with another `from` closes the socket with `1008 peer id is not the signed-in user`, and a second socket of the same user in one call is closed with `1008 peer id in use`.
- `ooxml-core/teams`, `openteams-server` and the OpenTeams bindings: a private chat's call now uses the signaling room `call-` followed by the chat's room name (`chatCallRoomId`). The server admits only the chat's members to it and refuses the `call-<workspace>-<chat id>` form that earlier clients used for a current chat id. Deploy the app and the server together.
- `openteams-server`: new default limits. Files have a ceiling of 1 GiB per uploader across every scope (`TEAMS_USER_QUOTA_MB`) and 20 GiB for the whole directory (`TEAMS_FILES_QUOTA_MB`, which used to be off). Stored rooms have a ceiling of 10 GiB (`TEAMS_ROOMS_QUOTA_MB`) and 10,000 rooms (`TEAMS_MAX_STORED_ROOMS`). Presence is capped at 64 KiB per client state, 4 MiB per room and 256 KiB per second per socket. A socket past a room or presence limit is closed with `1009 server storage full` or `1009 presence too large`.
- `openteams-server`: with accounts, an upload to a workspace scope that names no existing room is answered with 404.
- `openteams-server`: a client that has too many costly refusals in a minute (a chat join or chat file request refused after a room was read from disk, or a refused update) gets 429 for its sync sockets and chat file requests until the minute is over. The limit is 30 (`TEAMS_MAX_REFUSALS_PER_MIN`).

## Migration

- If your server runs with `authorizeSync` alone and its clients use file storage or calls, add an `authenticate` hook. For development only, pass `insecureDev: true`.
- Generate a session secret with `openssl rand -hex 32` and keep it outside the repository. A shorter or placeholder value now stops the server at start-up.
- Large installations should review the new file and room ceilings and raise them where needed (`TEAMS_USER_QUOTA_MB`, `TEAMS_FILES_QUOTA_MB`, `TEAMS_ROOMS_QUOTA_MB`, `TEAMS_MAX_STORED_ROOMS`).
- A third-party signaling server should check each signal's `from` against the signed-in user, and admit to `call-chat-<16 hex>-<chat id>` only the members of `chat-<16 hex>-<chat id>`. `chatRoomOfCall` in `ooxml-core/teams` gives the chat room of a call room.

## Added

- `ooxml-core/teams`: `createUpdateChecker(doc)`, which keeps one copy of a room document for the server-side checks, so checking an update costs time in proportion to the update instead of the room.
- `ooxml-core/teams`: `chatCallRoomId`, `chatRoomOfCall` and `isStrayChatCallRoom`.
- `openteams-server`: the options `userQuotaBytes`, `roomsQuotaBytes`, `maxStoredRooms`, `maxAwarenessBytes`, `maxRoomAwarenessBytes`, `awarenessByteRate` and `maxRefusals`, with the matching environment variables listed in the server's README.

## Security

- `openteams-server`: a server with only an `authorizeSync` hook signed a session for any claimed user and left file storage and call signaling open to anyone. Those routes are now closed on such a server.
- `openteams-server`: a signed-in user could join any call, speak in a call under another person's id and receive signals meant for that person. Call sockets are now bound to their signed-in user, and a private chat's call admits only its members.
- `openteams-server`: checking each update copied the whole room, and a refused chat join read the whole room from disk, so a signed-in user could stall the server for everyone with small messages. Checks now run on a copy kept with the room, refused joins are answered from memory after the first, and repeated costly refusals are turned away.
- `openteams-server`: presence had no size limit, so one socket could make the server hold and resend hundreds of megabytes. Presence is now capped per client, per room and per second.
- `openteams-server`: storage quotas could be sidestepped by choosing new workspace and room names. Uploads now also count per uploader and against a default ceiling, uploads need an existing workspace when accounts are on, stored rooms have ceilings, and a room nobody wrote to is not stored.
- `openteams-server`: a session secret copied from an example let anyone sign sessions for any user and role. Short and repetitive secrets are now refused, and the documentation shows how to generate one.
- `openteams-server`: an open socket kept its write access after its session expired. It is now closed at expiry.
