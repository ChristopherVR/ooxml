## Breaking

- `ooxml-core/pptx`: `inspectSignaturesFromBuffer` now verifies the signatures and returns a `SignatureSummary` (`{ state, signatures }`). `parseSignaturesFromBuffer` and `PackageSignatureInfo` are removed: they only parsed the signature parts and could not tell a valid signature from a forged one. See the migration guide.
- `ooxml-core/xlsx`: `Workbook.signatures` is now a `SignatureSummary` instead of `{ count, parts }`.
- `ooxml-core/docx`, `ooxml-core/xlsx`: loading a signed document no longer adds an English "signature not verified" message to `warnings`. Read `signatures.state` and word it with `signatureStateText` from `ooxml-core/i18n`.
- `ooxml-core/pptx/signature-node`: `canonicalizeNode`, `canonicalizeSignedInfoXml`, `getNodeLocalName` and `getFirstDescendantElementByLocalName` are no longer exported. Use `signature.canonicalize` from `ooxml-core/opc`.
- `ooxml-ui/pptx`: the building-block `DigitalSignaturesPort` supplies `summary()` (the deck's `SignatureSummary`) instead of `signed()` and `count()`. `describeSignaturesState` takes a `SignatureSummary`, and `SignaturesState` gains `state`, `signed` and `present`.
- `ooxml-ui/pptx`: `HostSignatureInfo` is the core's `SignatureEntry` (`path`, `state`, `signer`, `issuer`, `signingTime`, `validFrom`, `validTo`). The `expired` and `integrity` fields are gone.
- `ooxml-ui/pptx`: `loadPresentation` returns `signatures` (a `SignatureSummary`) instead of `hasDigitalSignatures` and `digitalSignatureCount`.
- `ooxml-ui/pptx`, PowerPoint viewers: the dictionaries no longer contain the unused keys `pptx.digitalSignatures.badge`, `badgeSigned`, `badgeTitle`, `headerSigned`, `invalidHeader`, `signed`, `statusValid`, `statusInvalid`, `statusExpired`, `statusUnknownCA`, `statusUnverified`, `serial` and `certificate`. Signature wording now comes from `signatureStringsFor` in `ooxml-core/i18n`.
- `pptx-react-viewer`: `pptx-react-viewer/internals` changed. `UseLoadContentInput` takes `setSignatures` instead of `setHasDigitalSignatures` and `setDigitalSignatureCount`, and `UseViewerDialogsInput` takes `signatures` instead of `hasDigitalSignatures`.
- `pptx-vue-viewer`: `pptx-vue-viewer/internals` no longer exports `useSignatures`, `UseSignaturesResult` or `OverallSignatureStatus`. `useSignatureWorkflow` takes a `SignatureSummary` ref and a locale and returns `view` instead of `signaturesApi` and `hasDigitalSignatures`. `useLoadContent` returns `signatures` as a `SignatureSummary` and no longer exports `parseSignaturesFromBuffer`.
- `pptx-svelte-viewer`: `PresentationLoader` has `signatures` (a `SignatureSummary`) instead of `hasDigitalSignatures` and `digitalSignatureCount`, and `Ribbon` takes `signatureView` instead of those two props.
- `pptx-angular-viewer`: `SignaturesService` and the signature helper exports (`isSigned`, `worstStatus`, `overallStatus`, `headerLabel`, `statusLabel`, `statusKind`, `signerName`, `signatureTimestamp`, `signatureKey`, `signatureCountLabel`, `OverallSignatureStatus`, `SignatureStatusKind`) are removed. `SignaturesPanelComponent` takes `summary` instead of `signatures`, and `LoadContentService` has `signatureSummary` instead of `signatures`, `hasDigitalSignatures` and `digitalSignatureCount`.
- `pptx-vanilla-viewer`: `ViewerState` has `signatures` (a `SignatureSummary`) instead of `hasDigitalSignatures` and `digitalSignatureCount`.

## Migration

- `ooxml-core`: show a document as signed only when `signature.isVerifiedSignatureState(summary.state)` (from `ooxml-core/opc`) is true. `hasDigitalSignatures` still says only that signature parts exist. The migration guide has before and after code.
- `ooxml-core`: `xml-crypto` is no longer needed as a peer dependency for signature verification.
- PowerPoint viewers: read `PptxData.signatures` and present it with `signatureStatusView(summary, locale)` from `ooxml-ui/pptx`. It gives the label, description, tone, icon and one row per signature, worded in the locale. Show a deck as signed only when `view.signed` is true. `view.present` says that signature parts exist, which is what the save warning needs.
- `ooxml-ui/pptx`: a host implementing `DigitalSignaturesPort` returns the loaded deck's `SignatureSummary` from `summary()` in place of `signed()` and `count()`.
- `ooxml-ui/pptx`, PowerPoint viewers: a host that translated one of the removed `pptx.digitalSignatures.*` keys can drop it; use `signatureStringsFor(locale)` from `ooxml-core/i18n` for signature wording.

## Added

- `ooxml-core/opc`: the `signature` namespace adds `verifyPackageSignatures`, `verifyPackageSignatureSummary`, `signatureStateOf`, `summarizeSignatures` and the `SignatureState` type (`unsigned`, `verified`, `verified-untrusted`, `invalid`, `unsupported`) verify the digital signatures of Word, Excel, PowerPoint and Visio packages in browsers as well as Node. They check the signature value, every signed part and that the signature covers the content. A browser has no trust store, so an intact signature from any signer is `verified-untrusted` there; the Node verifier still checks your configured trust roots and revocation.
- `ooxml-core/docx`, `ooxml-core/xlsx`, `ooxml-core/pptx`, `ooxml-core/visio`: a signed document carries its verified state as `signatures` (`model.signatures`, `Workbook.signatures`, `PptxData.signatures`, `VisioDocument.signatures`).
- `ooxml-core/i18n`: `signatureStateText` and `signatureStringsFor` word each signature state in English, French, German, Spanish, Simplified Chinese, Japanese and Korean.
- `ooxml-ui`: `<office-ui-signature-status>` shows a document's signature state from a `SignatureSummary` as a status bar badge (`variant="badge"`), a load notice (`variant="notice"`) or an info panel listing each signer (`variant="panel"`), worded in its `locale`. It emits `office-signature-activate` and `office-signature-dismiss`.
- `ooxml-ui/pptx`: `signatureStatusView`, with the `SignatureStatusView`, `SignatureStatusRow`, `SignatureTone` and `SignatureIcon` types, describes a deck's signatures for every badge, panel and notice.
- `ooxml-ui/pptx`: `signatureLoadNotice(view)` and `SIGNATURE_NOTICE_ID` give the notice a binding shows when a signed deck opens. `CompatibilityWarningToast` and the `pptx-ui-compat-toasts` element accept an already translated `text`.
- PowerPoint viewers: a signed deck opens with a dismissible notice of its signature state and the note that saving changes removes the signatures, translated in every UI language. It returns when another deck loads.
- `pptx-vanilla-viewer`: a signature badge under the ribbon that opens the Digital Signatures dialog, as the other bindings have.

## Changed

- Word viewers, Excel viewers, Visio viewers: a signed document shows its verified state in the status bar, in a notice under the ribbon and on File > Info: Signed, Signed (signer not verified), Invalid signature or Signature not verified, in every editor language. The notice says that saving changes removes the signatures. Nothing is shown for an unsigned document.
- PowerPoint viewers: the badge, the Digital Signatures panel and its rows show the verified state of each signature: Signed, Signed (signer not verified), Invalid signature or Signature not verified. A browser checks the signed parts' digests, the signature value and the signer certificate's key but trusts no signer, so a valid signature reads "Signed, signer not verified" at best.

## Fixed

- `ooxml-core/opc`, `ooxml-core/pptx`: signatures that Word, Excel and PowerPoint write are no longer reported as invalid in the browser. The previous check compared digests of the raw parts, which never match Office's signed references.
- `ooxml-core/pptx/signature-node`: a Word 2007 signature over pretty-printed relationships parts now verifies; the canonicalization used before rendered it differently from the signer.
- `ooxml-core/opc`, `ooxml-core/pptx`: a signature with a relationships part stored as UTF-16 now verifies, and PowerPoint reads UTF-16 parts instead of loading an empty deck.
- `ooxml-core/opc`: a signature that uses a method or key type the verifier does not implement is reported as `unsupported` rather than invalid.
- `ooxml-core/pptx`: a signed deck whose relationships parts the strict reader rejects (markup-compatibility attributes, for example) now opens instead of failing to load, and is shown as not verified.
- PowerPoint viewers: a deck with an invalid, forged or unverifiable signature is no longer labelled "Signed". Every binding used to show "Signed" whenever the deck contained a signature part.

## Security

- All packages: no product shows a document as signed because it merely contains a signature part. Badges, status bar entries, info panels and load notices in Word, Excel, PowerPoint and Visio show the verified state.
- `ooxml-core/opc`, `ooxml-core/pptx/signature-node`: checking a document's signatures can no longer stall the page, whatever the file holds. An RSA key under 1024 or over 16384 bits, or with a public exponent over 2^32, is not checked, and the signature reports `unsupported`. Each signature tries at most four certificates, reads at most 10,000 references and 100 MB of part data, and a signature part over 16 MB is skipped.
