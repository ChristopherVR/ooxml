## Breaking

- `ooxml-core`: `inspectSignaturesFromBuffer` (from `ooxml-core/pptx`) now verifies the signatures and returns a `SignatureSummary` (`{ state, signatures }`). `parseSignaturesFromBuffer` and `PackageSignatureInfo` are removed: they only parsed the signature parts and could not tell a valid signature from a forged one.
- `ooxml-core`: `Workbook.signatures` (Excel) is now a `SignatureSummary` instead of `{ count, parts }`. Word documents carry the same summary as `model.signatures`, PowerPoint presentations as `PptxData.signatures` and Visio drawings as `VisioDocument.signatures`.
- `ooxml-core`: Word and Excel no longer add an English "signature not verified" message to `warnings`. Read `signatures.state` and word it with `signatureStateText` from `ooxml-core/i18n`.
- `ooxml-core`: `ooxml-core/pptx/signature-node` no longer exports `canonicalizeNode`, `canonicalizeSignedInfoXml`, `getNodeLocalName` or `getFirstDescendantElementByLocalName`. Use `canonicalize` from `ooxml-core/opc`.

## Migration

- Replace `parseSignaturesFromBuffer(bytes)` and the `integrity` field of `inspectSignaturesFromBuffer` with `(await inspectSignaturesFromBuffer(bytes)).state`, or call `verifyPackageSignatureSummary(bytes)` from `ooxml-core/opc` for any Office format.
- Show a document as signed only when `isVerifiedSignatureState(summary.state)` is true. `hasDigitalSignatures` still says only that signature parts exist.
- `xml-crypto` is no longer needed as a peer dependency for signature verification.

## Added

- `ooxml-core/opc` verifies digital signatures of Word, Excel, PowerPoint and Visio packages in browsers as well as Node: `verifyPackageSignatures`, `verifyPackageSignatureSummary`, `signatureStateOf`, `summarizeSignatures` and the `SignatureState` type (`unsigned`, `verified`, `verified-untrusted`, `invalid`, `unsupported`). It checks the signature value, every signed part and that the signature covers the content. A browser has no trust store, so an intact signature from any signer is `verified-untrusted` there; the Node verifier still checks your configured trust roots and revocation.
- `ooxml-core/i18n`: `signatureStateText` and `signatureStringsFor`, the wording of each signature state in English, French, German, Spanish, Simplified Chinese, Japanese and Korean.

## Fixed

- Signatures that Word, Excel and PowerPoint write are no longer reported as invalid in the browser. The previous check compared digests of the raw parts, which never match Office's signed references.
- A Word 2007 signature over pretty-printed relationships parts now verifies; the canonicalization used before rendered it differently from the signer.
- A signature with a relationships part stored as UTF-16 now verifies, and PowerPoint reads UTF-16 parts instead of loading an empty deck.
- A signature that uses a method or key type the verifier does not implement is reported as not verified (`unsupported`) rather than invalid.
- A signed PowerPoint deck whose relationships parts the strict reader rejects (markup-compatibility attributes, for example) now opens instead of failing to load, and is shown as not verified.

## Security

- No product shows a document as signed because it merely contains a signature part. Badges, status bar entries, info panels and load notices in Word, Excel, PowerPoint and Visio show the verified state.
